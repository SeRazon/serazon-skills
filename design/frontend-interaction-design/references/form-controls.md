# 表单控件：Select 与 Dropdown

## 一句话区分

**Select 用于选择（填表），Dropdown 用于命令集合（下命令）。**

W3C 标准里只有 `select` 标签，没有"下拉菜单"这个标签；"下拉"是交互形态，不是组件语义。跟人说"做个下拉框"，很容易得到 Select，而你其实要的是"更多操作"。

| 维度 | Select 选择器 | Dropdown 下拉菜单 |
|---|---|---|
| 归属 | 数据录入 | 导航与操作 |
| 外观 | 必带外边框录入框，选中值回显在框内 | 纯文字或图标触发，点完立即执行 |
| 结果 | 等待提交，可再改 | 执行命令或跳转，不回填 |
| 例子 | 表单里的"性别""出生年份""状态筛选" | 表格行的"更多操作"：删除、导出、复制链接 |

## 一秒判断

- 点完之后**值回到框里**、还要随表单提交 → **Select**。
- 点完之后**发生了一件事**（删除、导出、跳转）→ **Dropdown**。

## 最容易翻车的现场

后台表格页：顶部"筛选框"（Select）与右侧"更多操作"（Dropdown）画得一模一样，用户点之前不知道这一下是筛条件还是删数据。

处理：顶部状态筛选用**带框 Select**；右侧操作用**纯文字/图标触发的 Dropdown**，并在菜单项上标危险色。两者不要互相模仿。

## 四条保命铁律

1. **只有 2 个选项严禁用下拉**：改用单选框或开关，否则操作步骤翻三倍。
2. **选项少于 5 个直接平铺**：摊在界面上，别让用户多点那一下。
3. **超过 10 个必须加搜索**：面板最高 **264px**，超出滚动，顶部固定搜索框。
4. **用户倒背如流的数据别用选择器**：生日、年龄、金额直接输入，比滚 100 行快。

## Select 的实现细节

- 多选用 chips 展示已选项，支持一键清空。
- 分组用 `optgroup` 或分组标题；禁用项必须注明原因（tooltip）。
- 键盘：`↑/↓` 移动、`Enter` 选中、`Esc` 关闭、输入首字母跳转；展开后焦点在选项上。
- 空结果给"无匹配项 + 清除搜索"，不要留白面板。
- 移动端优先用原生 picker（滚轮），除非需要搜索。

## 表单整体规范

- **label 常显**，不要用 placeholder 代替标签；必填标识全站统一（`*` 或"必填"）。
- 校验时机：失焦 + 提交时校验；输入过程中不打断，只在明显错误时提示。
- 错误文案 = 错在哪 + 怎么改；错误**不自动消失**，改对即清。
- 成功后**静默**：不弹"保存成功"遮住下一步，必要时用 Toast。
- 提交按钮：`loading` 态 + 防重复提交（幂等键）；网络失败保留用户已填内容。
- 长表单自动存草稿（本地 + 服务端各一层），返回时恢复。
- 字段宽度反映预期输入长度；`autocomplete` 属性写全，方便密码管理器与自动填充。
- Tab 顺序与视觉顺序一致；组内 Tab 到第一个可聚焦项，方向键在组内移动（单选组）。
