# 弹层选型与打扰分级

按"对用户的打扰程度"从轻到重排列。选型先看打扰度，再看内容量。

| 级别 | 组件 | 行为 | 适合 |
|---|---|---|---|
| 1 | Tooltip 文字提示 | 悬停出现、移走消失 | 解释图标含义；**关键信息不放这里** |
| 2 | Toast 轻提示 | 约 2s 自动消失 | "保存成功"这类无需操作的反馈 |
| 3 | Alert 警告提示 | 顶部黄条/红条，主动喊话但不阻断 | 全局状态告知、风险提醒 |
| 4 | Popconfirm 气泡确认 | 按钮旁小气泡，不用挪窝 | 高频、低风险的二次确认 |
| 5 | Drawer 抽屉 | 侧边滑出，背后列表仍在、焦点不丢 | 内容较长，或需对照列表 |
| 6 | Modal 模态弹窗 | 遮罩拦截，必须二选一才继续 | 关键决策 |

记忆法：Tooltip / Toast 是"悄悄告诉你"，Alert 是"大声提醒你"，Popconfirm 是"顺便问一句"，Drawer 是"边看边改不丢上下文"，Modal 是"不选不让走"。

## 每个组件的硬规则

- **Tooltip**：只做补充说明；可聚焦（键盘可达），显示延迟 300–500ms；不承载唯一关键信息。
- **Toast**：单行、可堆叠但不超过 3 条；不遮挡主操作；同一动作不重复弹。
- **Alert**：可关闭但不自动消失；区分 info / warning / error；文案写"发生了什么 + 该怎么办"。
- **Popconfirm**：锚定触发元素，箭头指向明确；按钮动词化（"删除""保留"）。
- **Drawer**：宽度 360 / 480 / 640 三档；保留触发点位置，关闭后焦点回到原按钮。
- **Modal**：只用于不可逆或高代价决策；同一时刻只允许一个。

## 内容多时：弹窗 vs 抽屉 vs 新页面

1. **看长短**：内容少用弹窗（400 / 520 / 720）；长表单换抽屉或新页面。
2. **看要不要对照**：需要一边看列表一边改 → 抽屉；彻底换流程（下单、付款、向导）→ 新页面。

## 三条防坑铁律

1. **填表弹窗别"点遮罩就关"**：必须加草稿自动保存；遮罩点击需二次确认或直接禁用。
2. **能撤销就别弹二次确认**：删除后给"撤销"条；只有找不回来的操作才弹窗拦。
3. **按钮别写"是/否"**：写具体动作——"放弃退票""确认扣费并退票"。

## 工程规范（容易被忽略）

- **层级**：`z-index` 分段管理，禁止随手写 9999。建议：内容 0 / 悬浮 100 / 下拉与 tooltip 300 / 抽屉 500 / 模态 700 / 全局提示 900。
- **焦点**：模态与抽屉必须做焦点陷阱（focus trap），打开时焦点进入首个可交互元素，关闭后**归还到触发元素**。
- **键盘**：Esc 关闭（AlertDialog 例外，见移动端规范）；Enter 触发主操作；Tab 不逃出弹层。
- **滚动锁**：打开时锁 body 滚动，并补偿滚动条宽度，避免页面抖动。
- **语义**：`role="dialog"` + `aria-modal="true"` + `aria-labelledby` 指向标题；Toast / Snackbar 用 `aria-live="polite"`，错误用 `assertive`。
- **动效**：进入 200ms、退出 120ms；遮罩透明度 0 → 0.4~0.5；减少动效偏好下改为淡入淡出。
