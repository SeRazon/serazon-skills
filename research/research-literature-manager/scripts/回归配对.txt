# 回归配对清单（每行：<原文文件名>\t<稿件文件名>\t<标签>\t<期望态>）
#
# ★ 这是**模板**，不含任何具体文献信息。
#   技能包里不该出现"测试用的是哪几篇真实论文"——那既泄露文献身份，
#   也让清单绑死在某个人的工作目录上（换台机器就全部"文件缺失"）。
#
# 用法：把本文件复制到你自己的工作目录，按实际文件名填第 1/2 列。
#   若一个都不填（只剩注释与负例行），回归测试仍会跑：
#     · 单元断言全绿
#     · 负例 fixture 被拦下（常驻，不依赖你的目录）
#     · 方向二假阳性测试（用合成原文自足运行）
#   这三项已能覆盖"门禁是否可信"，只是少了"对历史真实稿的复跑"。
#
# 第 4 列「期望态」语义：
#   pass    = 该稿**应当通过**（EXIT=0）。若被拦下 → 报「误杀」，是真问题。
#   violate = 该稿**应当被拦下**（EXIT=1）。若放行 → 报「漏报」，是真问题。
#   （缺省为 pass）
#
# ★ 为什么必须写期望态：
#   早先的版本不加区分地把「EXIT=0」一律判为「漏报！」，于是已修好的合规稿
#   每天都被打成多行「漏报！」+ 整体 EXIT=1。这是「把正常通过说成漏报」，
#   属于报告结论超出实际证据；更坏的是它会训练人忽略这个方向的告警。
#
# ★ 变更期望态时必须留痕（写在下方"变更记录"里）：
#   事实变了，改期望态不算"放松测试"；不改，才是让测试说谎。
#   但若没有留痕，后人分不清"同步事实"和"掩盖缺陷"。
#
# ── 变更记录 ─────────────────────────────────────────────
#   （示例格式，替换为你自己的）
#   · <标签> 在重写轮**之前**有 N 条硬缺陷 → 期望态=violate。
#   · 重写轮之后已修好（EXIT=0）→ 期望态**必须**改成 pass。
#     若发现有人把 pass 又改回 violate，那不是"恢复测试"，是把测试改回说谎。
# ─────────────────────────────────────────────────────────

# 在这里填你自己的测试稿（每行一份；不填也行）：
# <原文文件名>.txt	文献精读_<你的稿>.md	稿件1	pass
