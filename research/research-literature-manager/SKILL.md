# 科研文献精读与管理助手

把一篇文献**读透**，并把一批文献**管好**。

## 〇、最高优先铁律（不可变，任何情况下不得违反）

1. **交付契约**：客户给一篇文章，固定交付两件，缺一即违规、不增不减不改名——
   - ① `科研文献分类导航库.html`（库仪表盘）：文章归档后必须重建/更新；
   - ② `文献精读_<第一作者姓氏>_<年份>_<关键词>.html`（客户可见精读网页）：文件名按文章信息生成，**绝不用 `reading.html` 这类内部名**。
   - `reading.md` 是内部母版：只留底，**不算交付物、不呈现给客户**。
   - **只做到一半 = 违规**（只入库不出精读 HTML、或只出精读不重建仪表盘，都算未完成）。
2. **执行顺序**：**先精读、后入库**（精读只读 PDF、不依赖库，必须第一步）→ 收文 → 归档。`收文` 与 `归档` 连续执行、中间不停；**不许把 `收文` 的结果当成"验证通过"或进度汇报**。
3. **机器门禁（退出码是唯一判据）**：交付前必须跑、必须拿到 0——
   - `图数审计.py`（图数/七栏/必填栏位/字数闸）：
     `python scripts/图数审计.py --原文 <原文PDF或txt> --稿 <reading.md>`
   - `交付门禁.py`（两件交付物是否真存在）：
     `python scripts/交付门禁.py --id <条目标识>`
   - **不许把"命令跑通"当成"交付完成"**：验的是**东西在不在**，不是**流程跑没跑**。回报必须贴「OK/FAIL + 字节数 + 退出码」。
4. **命名（面向人显示的一律中文）**：专家名/技能展示名/标题/交付文件名/`科研文献分类导航库.html` 等一律中文；必须英文时用「中文（English）」括后。机器标识（本文件 `name`、包内根目录名、`scripts/` 内文件名）可英文。
5. **不许硬编码个人绝对路径**；不许在产物里写客户看不见的内部痕迹。
6. **只读不毁**：用户源文件（原始 PDF/Word）只复制、绝不移动或改写。

## 这个技能做什么

把一篇学术 PDF 拆成 **11 个板块**的结构化解读，产出可直接用于组会/答辩汇报的 Markdown 大纲；完成后自动归档进本地文献库（未分类），等你判定归类。

它不是摘要，是**带审计的精读**：数据和结论照抄原文，但同时把原文的缺陷、前后矛盾、不可复刻之处、能不能放心引用，全部点出来。

**什么时候不该用它**（别拿大炮打蚊子）：
- 只要 200 字摘要或一句话结论 → 直接读摘要，别跑 11 板块
- 只要某张图的数据 → 定位那一图看即可，不必全篇精读
- 纯综述、你只要脉络 → 只写板块 2 和 11，不必填方法与样本量
- 拿不到全文（只有摘要页）→ 明说仅基于摘要，不许编造正文细节

## 隐私边界（硬性）

**本技能不采集、不记录、不保存任何个人信息。**

- 不询问使用者的姓名、别名、单位、邮箱、账号。
- 不在产物、脚本、配置、注释、示例中出现任何真实自然人姓名（中英文）、邮箱、工号、单位内部信息。
- 不做"作者位次识别"：不判断读者是不是本文作者、是第几作者，更不据此调整内容。**只做文献本身的精读。**
- 产物里只出现**原文里写着的**作者名与单位，且**只保留原文形态**（原文是英文就写英文，原文是中文就写中文）。**一律不做音译、不做回译、不做推测补全。**
- 示例、模板、自测用例中的姓名/邮箱/单位一律使用明显虚构的占位形式（如 `Firstname Lastname`、`xxx@example.edu`、`某大学`）。

**机器门禁**：`scripts/隐私审计.py`（退出码 1 = 不许交付）。

```
python <技能目录>/scripts/隐私审计.py --skill-dir <技能根目录>
python <技能目录>/scripts/隐私审计.py --selftest        # 先自测门禁本身可信
```

- 查四类**结构性**痕迹：① frontmatter 个人元数据（`author:` 等带值）；② 身份采集机制（要求读者填自身信息的小节）；③ 非占位邮箱；④ 带具体用户名的本机绝对路径。
- **能力边界（不得读成"已确认无任何真实姓名"）**：它不识别"某串汉字是否为真实人名"。结论只能读成"**未发现上述四类结构性痕迹**"。
- **适用范围**：守的是**本技能今后的新产出**。历史存量稿（早期由已移除的"身份"功能写入过姓名与位次）按决定保持原样；若对其报出命中，那是**真实命中**，处置方式是确认"属历史存量、不作新交付物"，**不是**改稿，更不是放行。

## 环境准备（禁止硬编码路径）

换机器、换用户都不能崩。按顺序探测，**找到第一个能用的就停**：

1. 依次试这些 Python，哪个能 `import fitz` 就用哪个：
   - 受管环境：`<用户主目录>/.workbuddy/binaries/python/envs/*/Scripts/python.exe`
     （`envs/` 下可能有多个隔离环境，如 `default`、`cangjie`，逐个试）
   - 系统 `python`
   > **别照抄某台机器的绝对路径**——不同机器上受管环境的位置与名称都可能不同，
   > 按上面的通配形式扫描即可；找不到受管环境就退回系统 `python`。
2. 都装不了 PyMuPDF 就降级：能用别的方式把 PDF 转成 txt 就行，不强求某个库。
3. 路径一律用 Windows 盘符形式（`E:/...`、`C:/...`）。Git Bash 的 `/e/...` 会被错译成 `e:\e\...`，不要用。
4. 脚本用 `-c` 或脚本文件传入，别在命令行里拼长串中文路径。
5. **先确认文献库根目录，再跑任何 `litlib.py` 命令（否则第一次就会崩）**：
   - 库根解析顺序：环境变量 `LITLIB_ROOT` → 默认 `~/Documents/科研文献库`（`litlib.py:35`）。
   - **默认路径常常不存在**（实测：`~/Documents/科研文献库` 常常没有，用户可能把真实库放在别的盘）。
   - 报错形态具有迷惑性：不是"库根找不到"，而是 sqlite 底层的 **`sqlite3.OperationalError: unable to open database file`**（`litlib.py:66`）。
   - **处置**：先在各盘下定位真实库（`<盘>:/**/library.db`，深度 3 层内），再以环境变量指定：
     ```bash
     export LITLIB_ROOT="<真实库根>"   # 形如 <盘>:/<用户自选的库目录>
     python <技能目录>/scripts/litlib.py <命令>
     ```
   - **找不到 `library.db`** 说明是首次使用，此时才让它按默认路径新建。
6. **各脚本入参风格不统一，用前先看用法（不要凭习惯拼）**：
   | 脚本 | 入参风格 |
   |---|---|
   | `数字校验.py` / `图数审计.py` | 具名：`--原文` / `--稿` / `--out` |
   | `回归测试.py` | 具名：`--原文` / `--稿` / `--pairs`；**不支持 `--out`** |
   | `导航测试.py` | **位置参数**（目录或单个 html 路径），**不认 `--dir`** |
   | `视觉规格门禁.py` | 位置参数（输出目录）/ `--script-only` / `--update-baseline` |
   | `交付门禁.py` | 具名：`--id` |

## Phase 1：读取与清点

1. **提取全文**：先把 PDF 转成 txt 再读（不要试图直接读 PDF 二进制）。环境按上面的方式探测，不要写死。
2. **清点图表**：主图几个、补充图几个、有没有表格。记下总数，写进板块 6 开头。
3. **找元数据**：标题、期刊、卷期、文章号、DOI、PMID、投稿/修回/接收日期、版权、关键词。
4. **找作者与贡献**：作者列表、单位、通讯、作者贡献声明（CRediT 或段落式）。
5. **找数据可用性声明**：有没有 GEO/SRA/ArrayExpress 编号，还是"依请求索取"。这条直接决定板块 10 的评分，必须找到。
6. **补充材料**：拿得到就一并读；拿不到要明确写"本次未获得补充材料"，不要假装读过。
7. **把图渲染成图片，用眼睛看**（关键，不许省）：把主图所在页面渲染成 PNG，逐张读图。
   图注只告诉你"作者说这张图是什么"；看图才看得到柱高、曲线走向、散点分布、显著性标记（*/**/***）、有没有异常点。
   只抽图注文字做"图表解析"属于读文字推测，不是真解析。
   渲染不出来就如实声明"本次仅基于图注文字解析，未做像素级判读"，不许含糊带过。

## Phase 2：十一板块撰写规格

**长文分段写，别一口气生成**：11 板块 + 逐图解析很容易超单次输出上限被截断。按 1–5 / 6 / 7–11 分三段写，每段写完落盘再写下一段；中途被截断就从断点板块续写，不要把已写好的重写一遍。

### 板块 1　文献基本资料
- 标题（**英文文献**：英文原文 + 中文翻译；**中文文献**：中文原标题 + 英文译题，原文没给官方英文题就写原文未提供英文题，不要自己硬译）
- 期刊信息：期刊名（出版社）、年份、卷、期、文章号、是否预出版（Early View）
- DOI、PMID（原文未标注就如实写）
- 投稿节点：Received / Revised / Accepted 日期
- 版权与获取方式：CC-BY 还是订阅制
- 关键词
- 作者信息：第一作者、通讯作者（含原文标注的邮箱）、合作单位、作者贡献声明（CRediT 或段落式）。**不判断、不标注任何"本人位次"**——本技能只做文献精读，不涉及读者是谁。
- 文献类型判断：研究论文 / 综述 / 方法学 / 短通讯 —— **必须给判断依据**（有无标准论文结构 IMRAD、有无原始数据、结论是实验推导还是文献汇总）
- 研究层次：基础 / 转化 / 临床
- 基金与伦理合规：基金号、伦理批件、动物实验许可

### 板块 2　主要研究内容
- 要解决的科学问题（一句话）
- **研究对象本身的分量（硬性，不许只写"没人做过"）**：研究对象的流行学/临床/生态重要性——病原体的发现史、传播途径、全球感染规模、临床后果、为什么这个细胞/模型值得盯。
  - **为什么必须写**：实测教训——某短通讯篇我只写"NETs 在寄生虫中尚无报道"（179 字），对方写了病原体背景（1836 年首发现、性传播、临床后果、PMN 占白细胞 >60%）共 341 字。**"没人做过"只说明有空白，不说明空白值不值得填**。板块 2 的功能是让读者 30 秒内明白"为什么要做"。
- 假说或出发点
- 研究设计的逻辑链（怎么一步步往下走）
- 核心发现（一句话，后面板块展开）

### 板块 3　研究方法
逐项罗列，不合并。以下每类都要落到**可复制的具体参数**，不许只写方法名：
1. **研究设计类型**：基础机制 / 临床前 / 回顾性相关 / 生信再分析，并说明因果策略（基因扰动 + 回补 + 上位分析）
2. **模型**：
   - 基因工程动物：**构建路线写全**（靶向哪几个外显子、转录本编号、LoxP 插入位置、flox 区大小、显微注射 → F0 验证 → 回交、与何种 Cre 交配）
   - 细胞：逐个列出并注明用途（主力 / 对照 / 验证 / 工具细胞）
   - 移植模型：细胞数、注射部位、终点标准
   - 临床样本：组织芯片例数（癌 / 正常）、分期构成
   - 公共队列：队列名 + n
3. **关键技术**：每项给**操作参数**——离心力、温度、时长、抗体用量、交联条件、超声循环、试剂浓度、抑制剂浓度、质粒来源（Addgene 编号）、试剂盒货号、软件与版本
4. **关键变量**：分列**自变量**（全部扰动方式：KO/KD/OE、突变体、化学探针、营养状态）与**因变量**（全部读数：自噬读数、信号读数、稳定性读数、表型读数、临床读数）
5. **统计方法**：逐类列检验（t 检验 / 相关性 / 生存 / 多因素 / 组学校正），给出软件、归一化方式、显著性阈值与重复策略
6. **随机化与盲法**：写明动物是否随机分组、病理评分是否盲法、其余实验如何降低主观偏倚

### 板块 4　样本量
**四栏固定模板（每类样本都要落进这四栏，不许只填一栏）**：
| 栏位 | 内容 | 缺了会怎样 |
|---|---|---|
| ① 样本类型 | 到底测的是什么（细胞系 / 动物 / 组织 / 临床 / 公共队列 / 成像计数） | — |
| ② 样本来源 | 从哪来的（ATCC/STR、实验动物中心、医院伦理批号、数据库名称） | 读者无法判断可及性 |
| ③ 纳入与排除标准 | 怎么界定合格样本、有无剔除 | 读者无法判断选择偏倚 |
| ④ 每组样本量 | 每类每组的 n，及计数层级 | 读者无法判断统计功效 |

**为什么这四栏要固定**：实测教训——某短通讯篇我 70 字，只填了第 ④ 栏，其余是把板块 3/10 信息又抄了一遍，对方 222 字四栏全填。**把"样本量"做成"统计参数小结"是板块职责错位**：板块 4 的核心问题是"样本怎么界定、怎么纳入"，不是"n 等于几"。

**按样本类型分类列全，不许只给一个笼统的 n**：
1. **细胞系样本**：主力细胞系、补充细胞系、工具细胞各自 n，及来源鉴定情况（ATCC / STR / 支原体检测）
2. **动物分组与样本量**：每个动物实验分别给 n（表型队列、移植瘤、转移模型、IHC 计数），并给出**计数层级**（如"每 MG 15 个横截面 × 每截面 ≥30 细胞 × 3 只鼠"）
3. **组织 / 类器官样本**：组织芯片例数与分期拆分；**是否使用 PDX / 类器官要明确写"未使用"**
4. **公共队列样本量**：逐个队列给 n（含分期构成、分组人数、HR、中位生存时间）
5. **计数型成像样本**：每个成像指标各给 n（每条件统计多少细胞 / 切片）
6. **不适用说明**：无 power analysis、无前瞻入组等逐条写明
- 另需写明：误差线含义（SD / SEM / 95%CI）、统计检验、有无数据剔除

### 板块 5　研究时间
**要给完整时间点清单，不许只写"若干小时"；且要写成"实验时序"，不许只堆参数**：

> **写成时序，不是参数表（实测教训）**：某短通讯篇我只列了 4 条时间参数（刺激梯度、抑制剂预处理、虫培养、口径矛盾）共 66 字，对方 126 字——差别不在字数，在于对方写出了**先后关系**（何时刺激、何时孵育、何时读数），读者能还原实验动线；我的是散装参数，还原不出流程。**这一栏的产出物是"时间轴"，不是"参数清单"。**
1. **项目周期**：投稿 → 接收耗时；返修与数据更新节点；在线发表日期（确认不了就写"确认不了"）
2. **动物实验时点**：模型构建周期、表型观察窗（如"出生后 2 个月"）、给药周期、活体成像与取材终点、伦理批号
3. **细胞实验处理时点**：逐个实验给时间梯度——基因操作（KD/OE 多少小时/天）、自噬通量（抑制剂浓度与时长）、蛋白降解追踪（CHX 取样点）、饥饿与恢复（梯度 + 撤除后恢复点）、信号时程、功能读数（成球/侵袭/迁移各多少天）
4. **关键节点（穷举式盘点，不许挑选）**：凡原文出现**具体日期或时间刻度**的事件/政策/临床节点，**一律列出，不做取舍**。
   - 例：武汉 2020-03-19 本土零新增、北京新发地 2020-06-11 再现病例、珠海识别 76 例、香港 2020-01-17 起病例曲线、截至 2020-05-31 花费 25 billion USD……
   - **为什么必须穷举**：实测教训——曾在某篇只挑了自认为重要的 2 个节点（72 字），对比稿穷举 6 个（149 字）。**判断会漏，盘点不会。**这一栏是"给读者做时间轴"用的，不是"给作者做摘要"用的。
5. **不适用说明**：无临床随访窗、未说明批次间隔等，逐条写明

### 板块 6　图表解析（重头戏，篇幅最大）

**固定栏位模板（每图必须照这个顺序写，一栏不许省、不许合并）：**

```
#### 图表 N：<原文图号> — <原文英文标题>
- **原文标题**：<逐字抄原文图题（英文），不改写>
- **图注中译**：<A=…；B=…；C=… 逐条直译，n、剂量、浓度、时间、抗体用量、
  统计星号（*/**/***）与 p 值一个不漏>
- **图表类型**：<折线/柱状/热图/切片/散点/示意/共聚焦/明场…>
- **数据模式**：<分图逐条写组间差异，P 值、Kd、倍数、样本量写成具体数字。
  例："上皮面积 P = 0.0036"而不是"显著下降"——只有数字才可被复核>
- **学术意义**：<这一图在全文论证链中的位置（上位/下位），提供哪一类证据
  （必要性/充分性/相关性）>
- **统计方法**：<本图用了什么检验，如 one-way ANOVA+Tukey / repeated ANOVA+Bonferroni / t test / nonparametric>
- **本图数值清单**：<列出本图全部可复核数值：P 值、n、浓度、时长、Kd、分子量、倍数>
```

> 为什么这七栏是固定顺序：逐字抄原文标题是为了防止"自己起个短标题"（实测我 5 篇稿把英文原题改成自拟中文短标题，导致无法与原文对照）；分列"数据模式"与"数值清单"是为了让板块 9 的矛盾核对能直接引用；"统计方法"单独一栏是因为它最容易漏（实测我 6 篇稿里"统计："只出现 2 次）。

**主图与扩展数据图都要逐个解析**，每图固定按上面七栏写，一栏不许省。

**补充图与补充表必须逐个解析（硬性，不许只报总数）**：
- 禁止出现类似"全文 7 幅主图 + 7 幅补充图 + 5 个补充表"然后就跳到 Figure 1 的写法——这是**漏做**，不是精简。**此条由 `scripts/图数审计.py` 机器强制，不过门禁不许交付。**
- **严禁用"补充图本次未获得"当不解析的理由（红线，实测教训）**：
  - **"未获得原件"和"不能解析"是两回事。** 绝大多数情况下，正文里对补充图内容有明确描述（如"时间梯度 30/60/90/120 min""MOI 3:1/6:1/12:1""p38 与 ERK 磷酸化"），**完全可以依据正文写出与主图同等规格的条目**。
  - 实测教训：某短通讯篇我写了"补充图本次未获得，其内容仅能依据正文转述"，然后**零解析**——这是**措辞性遮盖**：把"没做"包装成"做不了"，**比直接漏更严重**，因为它让漏看起来合理。
  - **正确做法**：正文有描述的，按正文口径写成完整条目，并在「原文标题」栏标注"（依正文）"；正文也没描述的，才可写"原文正文未描述该图内容，无法解析"，并**单独列进缺失清单**。两种情形都**必须有条目**，不许一条不写。
- **补充图使用与主图完全相同的七栏模板**，不得因为"是补充材料"就降级成一行摘要。
- 补充图按"验证什么"归并成簇可以（如"补图 1–2：方法学验证"），但**每簇必须逐个点名并说清它支撑了正文哪一条结论**。
- 补充表要逐个说明是什么数据（峰坐标 / FPKM / 基因列表 / 引物序列），并判断它是否构成"原始数据可得性"的加分项——注意：**补表公开 ≠ 原始数据可再分析**，若全文无 GEO/SRA 编号，仍应记为可复刻性障碍。
- 补图里常见的"突变体特异性 / motif 重叠度 / 亚细胞定位"信息，是判断"对照是否干净"的关键，**漏掉等于漏掉局限性分析的弹药**。
- **补充图解析完必须挂回正文证据链**：板块 7 里每条结论的证据强度标注，若其依据来自某补充图，必须写明来源图号（实测教训：某篇的 S11 是抑制剂体内回补实验、是"靶点位于上游"的体内闭环证据，我漏挂了，导致证据链只写了一半；另一篇的 S1/S2 是板块 7「量效证据」的唯一依据，我把结论挂在了自己没解析的图上，证据链同样是断的）。

### 板块 7　主要结论
**两层结构**：
1. **核心发现分条**（每条必须带具体数值：P 值、倍数、Kd、HR、中位生存等，不许写"显著上升"就完事），每条标注证据强度：
   - 【必要证据】敲除/敲低后表型消失
   - 【充分证据】过表达/回补后表型复现
   - 【相关性】只有关联，无因果操作
2. **学术意义**：分层面写——概念层面（提出了什么新范式）、机制层面（新增/修正了哪条通路）、表观/翻译后层面、发育与疾病的关系、转化层面（可干预靶点与路径）。逐层都要落回本研究的证据，不许泛泛而谈。

### 板块 8　创新点
**分四类写，每条都要指向本研究的哪一项证据**（四类都要给，缺哪类就写"本文无此类创新"并说明理由）：
1. **理论创新**：新复合物 / 新机制 / 新范式，对既有认知的修正或补充，逐条对应证据
2. **方法创新**：正交验证链、因果解耦工具（如只破坏互作不破坏蛋白的突变体）、降解路径归属判据、多读出交叉验证、结构-功能双向解耦、**阴性结果（排除法）的系统呈现**
3. **命名 / 概念提炼创新**：作者是否**新造术语、统一命名、或给既有现象起了新名字**（如把某类流调命名为 PEI）？
   - **"命名"本身就是学术贡献**，它把一个散落的现象变成了可被引用的概念。
   - 遇到作者新造/推广的术语，**必须单列一条**，并注明：这个术语是本文首创、还是本文沿用但首次系统化。
   - **为什么单列**：实测教训——我曾把某篇新命名的 PEI 只当成一个内容点，漏掉了"命名即创新"这个维度，导致该板块比对方少一条维度。凡是综述/评述类文章，命名往往是它最主要的知识增量。
4. **应用创新**：可药化界面是否明确到残基级、有无概念验证化学探针、有无生物标志物读数、能与哪些已有疗法联合

**每类后面必须给星级（硬性，不许用自造的"增量"这类笼统词替代）**：`⭐⭐⭐⭐⭐` = 领域突破 / `⭐⭐⭐⭐` = 重要 / `⭐⭐⭐` = 有一定增量 / `⭐⭐` = 增量很小 / `⭐` = 基本无。
- **为什么必须分级**：实测教训——某篇我用自造的一个词"创新评级：增量"盖过全部，读者无法知道"到底是理论强还是方法强"；对方分理论/方法/应用三类并各给星级。**一个笼统评级 = 没做分解。**
- 每条星级后附**一句依据**（指向该条依赖的具体证据）。

5. **总体创新评级（按锚点打，不许凭感觉）**：
  | 评级 | 锚点 |
  |---|---|
  | 突破 | 推翻或改写领域既有结论，或开辟新方向 |
  | 重要 | 首次证实某机制/靶点，或方法学明显优于现有方案 |
  | 增量 | 在已有框架内补一个环节，或换新模型再验证 |
  | 重复验证 | 已知结论在新体系里再验一遍，无新认知 |
  打完必须附：**依据（逐条）** + **相对短板**（指向板块 9 的局限），不许只给一个评级。
- 临床/转化价值（如果原文声称了，标注是"作者声称"还是"已验证"）

### 板块 9　局限性
**分三层写，一层都不许省**：
1. **作者自述的局限性**（Discussion / Reporting Summary 明确写的）
2. **我识别出的局限性**（你独立看出来的，这是精读增值所在）
3. **对结论的影响判断**：逐条判断这些局限**是否动摇核心因果链**——明确写"不影响核心链，理由 X"或"某一环因此不能成立"；不许只罗列局限而不下判断

重点找这些：
- 数据未公开（无公共库编号，无法独立重分析）
- 剂量/单位/数值前后不一致（**逐处核对，给出具体位置和矛盾内容**）
- 单位排版错误（如 µm 与 µM）
- 只有单一性别/单一物种/无人源样本
- 缺阳性药对照、缺关键回补实验（如只在体外做了回补，体内没做）
- 对照组本身不惰性（对照也有效应）
- 样本量小、无样本量估算（power analysis）
- 关键方法学存疑（如外泌体用 PEG 沉淀而非超速离心）

### 板块 10　研究可复刻性
- **总体判断**：可复刻 / 有条件可复刻 / 难以复刻，并给理由
- **分维度评分表**（每行：维度、评分、说明）：
  模型可获取性、试剂与序列公开度、仪器与方法记载完整度、原始数据可得性、统计方法清晰度
- **评分锚点（五档，五个维度用同一把尺子，不许凭感觉）**：
  | 档位 | 含义 |
  |---|---|
  | 5 全公开 | 该维度所需的一切在原文或补充材料里能直接拿到 |
  | 4 基本够 | 关键信息有，个别细节按常规方案自行确定即可 |
  | 3 部分缺 | 缺关键序列/货号/参数，但可依领域常规推断 |
  | 2 严重缺 | 核心步骤描述含糊，须与原作者确认才能动手 |
  | 1 不可得 | 数据/材料明确不公开，且无替代路径 |
  每维打完必须写一句依据（写了什么、缺了什么）；总体判断取五维结论汇总，不要孤立地给分。
- **缺失清单**（最实用的一栏）：把复刻必须但原文没给的东西逐条列出——序列（sgRNA/引物）、抗体货号、关键参数、软件版本、数据编号
- **可引用金句（硬性，≥3 条）**：固定小节，格式为 `"<英文原文>"（<中译>）—— <位置/页码>`。
  - **选句标准**：① 能代表本文核心主张的结论句；② 机制/概念定义句；③ 有量化数字的发现句。
  - **用途**：写申请、做汇报、写引言时可直接摘用；没有这一栏，就得自己回原文翻。
  - **为什么硬性**：实测教训——某篇给了 3 条（含页码定位），另一份**一条都没有**，导致该板块少 167 字。可直接引用的原文句子是精读产物里使用频率最高的部分。
- **可迁移要素**：写清本文的证据/方法里哪些是**可跨课题复用**的（可直接借用、需改造后借用、不可借用的分别是什么），侧重"可复刻的要素"。
- 结论一句话：方法论层面能否复现，数据层面能否独立再分析

### 板块 11　核心要点总结
- **100 字概括**，分三行：最核心问题 / 最关键方法 / 最突出发现
- **三要点总结**（Take Home Tips）：3 条，每条带关键数据
- **引用建议**：哪些结论可以放心引，哪些只能引机制不宜引前景（这条来自前 10 个板块的审计结论）

python <技能目录>/scripts/隐私审计.py --selftest        # 先自测门禁本身可信

### 第一步：跑视觉规格门禁（硬性，不过不许交付）

**2026-09-20 新增。起因是一个直接提问："该 skill 产出的版式、字体、颜色、排版等参数是否已固定？保证每次精读任务不会变化整体风格？"**

**核实后的诚实答案：当时并不"固定"，只是"恰好一致"。** 三条证据：
1. 版式全部写死在 `templates/精读转网页.py` 的 CSS 常量里，**没有独立配置文件**；
2. 当时 5 个门禁脚本对 CSS / 字号 / 颜色的校验**命中 0 处** —— **没有任何机器在守它**；
3. 6 份 HTML 的 CSS 逐字节一致，但那是"已经生成过的一致"，**不是被强制的一致**：下次只要 CSS 常量被改动，没有任何东西会报警。

```
python <技能目录>/scripts/视觉规格门禁.py <输出目录>      # 校验
python <技能目录>/scripts/视觉规格门禁.py --script-only    # 只校验脚本 CSS 常量
```

- 它做三件事：① 逐条断言 **28 项**关键视觉参数仍在（12 个 `:root` 变量 + 各字号 + 字体栈 + 栅格）；② 用 sha1 基线校验脚本 CSS 是否被改动；③ 校验产出的 `.html` 是否与脚本 CSS **逐字节一致**（防止有人手改 HTML 而绕过脚本）。
- **退出码 1 = 不许交付**。
- **改样式的唯一正确流程（三处必须同时改，缺一不可）**：改 `templates/精读转网页.py` → 跑 `--update-baseline` → 同步本文件下方「详情页视觉规格」表。少改任何一处，就是"规则与实现脱节"。
- **能力边界（不得读成"样式一定好看"）**：它只校验**样式声明的一致性**，拦得住"参数被改动"，**拦不住**"参数没改但正文内容导致排版差异"（超长表格、超长英文词撑破容器）——后者须人工看图。

### 第二步：跑人名审计门禁（硬性，不过不许交付）

**这一步放在最前**，因为人名错误是**一眼可见的学术信誉损伤**，且极易批量犯（曾在五篇稿里编造 15 个中文人名）。

```
python <技能目录>/scripts/人名审计.py --dir <输出目录>
python <技能目录>/scripts/人名审计.py --selftest     # 先自测门禁本身可信
```

- 判定：**退出码 1 = 禁止交付**。逐条核实每个"英文名（中文）"，**无据者删掉中文名，只留英文原名**。
- **规则：原文没有汉字，稿件里就不许有人名汉字。零豁免。**
  - **不许**由拼音倒推（`Samplefull Zhang` ✗"张甲"）
  - **不许**拿邮箱当依据（邮箱推不出汉字）
  - **不许**靠加一句来源说明绕过（加了说明，汉字照样是猜的）
  - **不存在"使用者本人姓名"这类豁免** —— 本技能不记录、不比对任何真实姓名
  - 正确写法：`Li-jun Di（某大学；邮箱 xxx@example.edu）`——单位与邮箱照录，不加中文名
- 门禁内置双向自测（13 条断言），既验证"能拦住编造"（含明确否决的三种写法），也验证"不误伤术语中译与单位名"。

### 第三步：跑图数审计门禁（硬性，不过不许交付）
**这一步必须放在数字校验之前**，因为"漏解析补充图"是本技能历史上反复出现、且**加文字规则也拦不住**的头号缺陷（多轮对比复盘均证实：连续数篇漏掉 6–11 幅补充/扩展数据图，共同点都是"报了总数就跳过"）。

```
python <技能目录>/scripts/图数审计.py --原文 <原文txt> --稿 <我的精读.md> --out 图数审计报告.md
```

脚本做六件事：
1. **从原文自动数图**：识别三种命名体系——`Figure N`（主图）、`Figure S1`（S 编号补充图）、`Extended Data Fig. 1`（扩展数据图，Nature 系用）、`Supplementary Fig. 1`（纯数字补充图，部分期刊用）、`Supplementary Table N`（补充表）。已处理：PDF 转 txt 的软换行（`Extended \nData Fig. 1`）、编号后缀（`Figure S1A`）、**复数缩写与列表形式**（`Supplementary Figs. S1 and S2` / `Figure S1, S2` / `Figure S1–S2`）。
   > 列表形式是 2026-09-20 修掉的真实 bug：某篇原文写 `Supplementary Figs. S1 and S2`，旧正则只认 `Figure/Fig.` 单数，导致 S1、S2 被整段漏掉，原文 3 幅补图只报出 1 幅（S3）——**门禁漏报会让缺陷被低估**。
2. **从稿件数解析条目**：统计 `## 图表 N / ## Figure N` 条目数，并抽取板块 6 里引用到的全部图号。
3. **求差集**：原文有、稿件没提的补充图 → **逐幅列名报错**。
   - **关键设计：声明句不算解析**。稿件开头"全文 7 幅主图 + 7 幅扩展数据图（Extended Data Fig. 1–7）"这类**声明句会被先挖掉**再统计覆盖。
   - 实测教训（第一次修）：旧逻辑被 `Extended Data Fig. 1–7` 的取值范围骗到，把两端 XD1/XD7 判成"已覆盖"，于是只报"缺 XD2–XD6"，**实际 7 幅一幅没解析**。改动后正确地报"7 幅零解析"。
   - **实测教训（两次反转）**：
     - ① 为修上一条而写的"声明剥离"正则 `全文[^。\n]{0,40}...` 是**贪婪**的，会把同一行里的真实解析一起挖掉（`……共 5 幅主图……，Supplementary Fig. S1 显示时间依赖。` → 挖成 `如图 1 所示， 。`），**凭空制造"零解析"假判决**。已改为**按分句剥离 + 含具体图号的分句一律保留**。
     - ② 更隐蔽的一层：稿件声明常写成 `7 幅主图（Fig. 1–7）+ 7 幅扩展数据图（Extended Data Fig. 1–7）+ 5 个补充表`，若**按 `+` 切分**，只有首段带"全文"触发词能被剥离，后段残留 → 首尾编号被算作"已解析"，仍报"缺 5 幅"而非"7 幅零解析"，**凭空替稿件认了 2 幅**。已取消按 `+` 切分。
     - **这两条的方向标定**：挖多了 = 谎报缺图（同"内容失真"，是**伪造证据**）；挖少了 = 漏报。两者都错，但前者更坏——它让报告**在无证据的情况下断言**。因此剥离逻辑采用准入式：**只有能精确定位到声明片段时才挖，定位不了就保留**。
4. **查板块 6 固定栏位**：原文标题 / 图注中译 / 图表类型 / 数据模式 / 学术意义 / 统计方法 / 本图数值清单 **七栏**，少于图条目数逐栏提示。
5. **全文级必填栏位硬拦（不通过级）**：`可引用金句 ≥3 条`（按编号列表计数，不是数"金句"二字）、`关键节点穷举 ≥1`、`创新星级 ≥4`。这些栏位"少写也不显眼"，必须机器拦。
6. **板块字数闸（提示级）**：板块 2/4/5/6/8/10/11 各有建议下限，低于则提示，并在提示里写明**为什么这条下限存在**（对应哪条实测教训）。

**退出码 1 = 不通过 = 不许交付**。不通过时必须回去补解析，补完重跑，直到通过。

**脚本的实际能力边界（不得把"通过"读成"合格"）**：

| 能查 | 查不了（必须人工读） |
|---|---|
| 原文图/表编号 vs 稿件板块 6 引用编号的**差集** | 图注中译的**翻译质量** |
| 板块 6 七栏的**关键词出现次数** | 「本图数值清单」里的数字**是否真在原文中**（有栏位 ≠ 数字对） |
| 四条全文级必填栏位是否**存在** | 图与结论的对应是否成立 |
| 板块 2/4/5/6/8/10/11 的**中文字数** | 板块 7–9、11 的论证质量 |

另外三种它看不见的情形，报告里已显式声明：**表格内部数据与图中标注上的数字**（不在文本正则范围）、**栏位写满但内容重复/模板化**（关键词计数无法识别）、**图号被引用但只写了一句空话**（差集只看图号是否出现）。

**结论措辞**：报告的"通过"仅指"未触发上述可机检项"，**不等于稿件合格，也不构成对内容正确性的担保**。报告出现"不通过"时，只声明机器发现了什么，**不断言真实缺陷的全部范围**。

**★ 报告里的"栏位缺失提示"必须先回原文逐条核对，不许照提示盲改稿件（2026-09-21 实测）**

报告除了结论，还会打印若干条"第 N 条图缺某栏"的提示。**这些提示本身也会误报，原因与上面第 8 条同源：脚本按"图条目"切块，会把正文表格也算进去。**

- **实测案例**：某稿提示 `图注中译 6/7 缺`、`图表类型 6/7 缺`、`数据模式 6/7 缺`（3 条）。逐条回原文核对后确认为**误报**——真正缺栏的第 7 条是 `## 图表 7：Table 1 — 引物序列（正文表格，非图）`，**表格本来就没有这三栏**；前 6 条图条目（Fig. 1–5 + Figure S1）七栏**全齐**（用自写切块脚本逐条断言，`MISSING: []`）。
- **处置铁律**：提示只是**疑点清单，不是修改指令**。必须**先回原文确认那条到底该不该有这三栏**：
  - 若原文该图表**本就无此类栏位**（表格、纯序列、纯参数表）→ **判误报，不补栏**。**为了消掉提示而给表格硬塞"图注中译/图表类型/数据模式"，等于往交付物里灌水，比留着提示更有害。**
  - 若原文该图表**确应有**该栏而稿件漏写 → 才是真缺陷，回去补。
- **口径代价（必须说清，不许含糊）**：报告"通过（EXIT=0）"与"栏位缺失提示 N 条"**可以并存**，这是设计使然——提示不计入退出码判据。所以**不许把"EXIT=0"复述成"零提示、零问题"**，也不许把提示数当成缺陷数往台账里记。**两者都要如实报给客户/台账，并标明哪几条经核对判定为误报、依据是什么。**

#### 改过脚本之后：必须跑双向回归测试（红线 24）

门禁自己也会错，所以**每次修改 `图数审计.py` 都要跑回归测试**，三个方向都要测：

```
python <技能目录>/scripts/回归测试.py --原文 <原文txt目录> --稿 <稿件md目录> --pairs <技能目录>/scripts/回归配对.txt
```

- **方向零（单元）**：门禁内部逻辑断言（当前 **40 余条**），每条对应一次真实误判。改动脚本后这里变红 = 修复被改回退了。
- **方向一（假阴性）**：按配对清单**第 4 列声明的期望态**逐篇核验。
  - `pass`（应通过）而拿到 EXIT=1 → **误杀**，是真问题。
  - `violate`（应被拦下）而拿到 EXIT=0 → **漏报**，是真问题。
  - ⚠️ **不许把每篇 EXIT=0 一律判"漏报"**：稿件重写后它们**本来就该通过**，那样报是把正常通过说成缺陷（狼来了）。期望态由配对文件显式声明，**事实变了必须同步更新，并留痕写明为什么改**。
- **方向二（假阳性）**：脚本会**按该原文的真实图数动态生成一份合规稿**（写死图数的 fixture 会造成假失败），确认它能通过（EXIT=0）。若被误杀，说明门禁过严。
  - **没有可用真实稿配对时，自动改用合成原文**（2 主图 + 3 补充图 + 1 补充表）跑，**不跳过**——方向二检验的是"门禁会不会误杀好稿"，与"手上有几篇真实稿"无关。
- **`回归配对.txt` 是可填模板，不是快照**：技能自带的清单只有负例 fixture 那一行，不含任何具体文献信息。要复跑自己的历史稿，**复制到你自己的工作目录再填第 1/2 列**。这样做有两个理由：① 技能包不该暴露"测试用的是哪几篇真实论文"；② 硬编码某人机器上的文件名，换台机器就全部"文件缺失"，防线静默失效。
- 退出码 0 = 三个方向都符合预期。

**★ 负例必须常驻，不能只活在别人的稿子里**（真实教训 M31）：方向一原设计依赖"目录里恰好有一篇坏稿"。全部稿件修好后这条防线**静默退化成只测 pass 项**，且无人察觉。故新建

```
scripts/负例_原文.txt   scripts/负例_稿件.md
```

这是一份**故意不合规**的常驻 fixture（缺补充图 S1、缺每图「统计方法」栏、缺两条全文级必填栏位），配对清单里以 `violate` 承接。并加了一条**元断言**：fixture 必须仍被拦下（EXIT=1）——**防止它日后被谁（包括我）顺手改好，使防线无声失效**。

  **新增红线 27（唯一实现原则）**：凡"同一事实在脚本里有两处实现"，改一处必留另一处——**修改前先 `grep` 出全部实现路径，改完再 grep 一次确认清零**；关键计数必须收敛为唯一函数。
  **新增红线 28（诚实声明不得被计为缺陷）**：稿件里"如实声明 0 图/0 表/未读到"的收尾块，**不得**被当成图条目或缺陷证据——**门禁必须鼓励诚实，不许惩罚诚实**。
  **新增红线 31（图条目识别口径必须显式写出）**：`#`~`####` 级标题 + `图表 N` / `Figure N` / `图 N` 前缀；含"盘点/声明/无表/合计"等收尾语义词的标题**不算**图条目。**口径写进报告，是因为"识别不到"和"没问题"在输出上长得一样**——不写出来，读者无法自查是否被漏认。
  **新增红线 32（测试的期望态必须与事实同步）**：写死的期望态不会自己跟着事实变，只会变成假警报。**事实变了，改期望态不算"放松测试"，不改才是让测试说谎。**

### 第四步：跑数字校验（不要只靠自查）

成稿后跑一次数字校验脚本，拿它的报告来写板块 9、10：

```
python <技能目录>/scripts/数字校验.py <原文txt> --out 校验报告.md
```

脚本输出四类东西：同参数不同数值的位置清单、单位可疑写法（如 µm/µM 混用）、样本量与 p 值清单、**纯整数矛盾**（433/443 型）。

**脚本只给候选，判断靠你**：同一参数在不同实验里取不同值是正常的（不同给药时长、不同细胞系），要逐条回原文核对，确认是真矛盾还是正常差异。确认是真矛盾的，必须写进板块 9 并注明"见板块 10"。

### 第五步：同批交付横比（一次交多篇时硬性）

**一次交付多篇时，交之前必须把各篇的板块 6 字数与图条目数并排列出来**，最短的那篇必须说明为什么短。

**背景（实测教训）**：某次同批交付 6 篇，板块 6 中文字数为 615 / 1,518 / 1,092 / 758 / 645 / 5,796——**最大最小差 9.4 倍**，而交付前没有任何横比动作，导致最该做厚的那篇（作者自己的独立一作）成了最薄的一篇。

**规则**：图条目数 < 原文图总数（主图 + 补充图）即视为未完成，不论理由。字数最短的篇目若不给出可核查的短写理由（如"原文仅 2 图"），视为赶工。

### 再过红线

写完必须过一遍这些硬规矩，**违反任何一条就返工**：

1. **数字、浓度、样本量、p 值一律来自原文**，禁止估算、禁止外推。
2. **单位错误要单独标出**，注明"原文排版缺陷"。
3. **前后矛盾必须交叉核对**：同一参数在不同章节/图注/方法里出现多次时逐个比对，不一致就写出来（几处、分别是什么）。
4. **未公开的数据必须记为可复刻性障碍**，不能默认别人能拿到。
5. **图表解析必须到分图（panel）级**，不能只说"图 1 显示了疗效"。
6. **补充材料没读到就明说**，不得臆测内容。
7. **板块间做交叉引用**：前面提到的缺陷，在后面板块写"见板块 9/10"，保持全文一致。
8. **作者位次按身份配置核对**，命中就标，没命中不硬套。
9. **区分"作者声称"与"已验证"**，不要把 Discussion 的推测写成结论。
10. **程序化校验必须回原文逐条核对（硬性）**：脚本只给候选清单，**不许跑完脚本就写"未发现异常"**。逐条回原文核对每一条嫌疑，把核对结论（真矛盾／正常差异／疑似笔误）写进稿子；漏掉真实矛盾视为未完成。
11. **内部引用一致性专项核对（硬性）**：把**位点编号、数值、图号**在"正文 ↔ 图注 ↔ 图内标注"三处交叉比对，任何一处不一致都要单列（例：正文写 K193 而图注写 K194R；正文 Kd 写 10.6 µM 而图中为 10.9 ± 3.9 µM；正文图号与图注图号不符）。这类不一致人工最容易漏，也最能体现实力。
   **纯整数专项（清单里必须有这一栏）**：基因数 / peak 数 / 例数 / 细胞数 / 组数这类**不带单位的纯计数**，脚本虽已能扫（见 `数字校验.py` 的"整数矛盾"栏），但**漏报率仍非零**，必须自己再通读一遍，重点盯**同一段话里前后两个计数是否自洽**。
   实战教训：某文同一段先写 "Four hundred thirty-three genes"（英文数词写法）、紧接写 "these 443 genes"（阿拉伯数字写法），**同一段内 433 与 443 冲突**——这是最隐蔽的一类（同一个数字换了两种写法），当时脚本与人工双双漏检。**凡遇到"作者用英文数词 + 阿拉伯数字混写同一个量"的情况，一律当高优先级嫌疑。**
12. **看图不许静默降级**：主图页面必须渲染成 PNG 实际判读；确实做不到时，必须在稿中写明降级**理由**（体量过大／渲染失败／原件缺失），不许只写一句"未做像素级判读"了事。
13. **中文显示铁律（硬性）**：所有标题、板块名、名称、显示文字一律**中文在前**，英文只能作括注跟在后面（例：研究方向（research_topics））。**不得出现英文主导的显示**。专业术语首次出现可括注英文，此后用中文。
14. **补充材料必须逐条解析（硬性）**：板块 6 除 7 幅左右主图外，**补充图（Supplementary Figure）与补充表（Supplementary Table）必须逐个出现并解析**，按功能簇归并可以，但**不许只写一句"另有 7 幅补充图"就跳过**。补图里往往藏着突变体特异性、motif 重叠度这类"判断对照是否干净"的关键信息，漏掉等于漏掉局限性分析的弹药。
15. **图注中译必须逐条、不落数字（硬性）**：图注 a/b/c… 每一小项都要译出，**样本量 n、剂量、浓度、时间、抗体用量、统计星号（*/**/***）与 p 值一个不漏**。把图注"概括成一句话"不算翻译，算摘要——本技能的图注栏要的是翻译，不是摘要。
16. **每图必须有"本图数值清单"（硬性）**：每幅图解析完，**在该图小节末尾单起一行**列出本图全部可复核数值（P 值、n、浓度、时长、Kd、分子量、倍数），供板块 9 的矛盾核对直接引用。数值清单散落在正文各处 = 没写。
17. **交付前查字数下限**：11 板块正文中文字数**低于 6,000 视为写得太浅**，需回查是否漏了补充材料、图注翻译或数值清单。
18. **板块 11 除三要点与引用建议外，固定加一节「可迁移要素」**：写清本文的证据／方法里哪些可跨课题复用（可直接借用 / 需改造后借用 / 不可借用，分别是什么）。只给通用总结、不落到"能不能拿走用" = 等于没写。**（原「对本人的用法」个性化小节已按上架合规要求删除：本技能只做文献精读。）**
19. **图数审计门禁不过，禁止交付（硬性，最高优先）**：成稿后必须跑 `scripts/图数审计.py`，**退出码为 1 时一律不许交付**，必须补齐缺失图条目后重跑至通过。
    **背景（必须记住）**：这条红线是用血换来的。多轮对比复盘证实——**"补充图零解析"是本技能排名第一的缺陷，且加文字规则（红线 14）完全拦不住**。实测证据：三篇稿分别漏 6 幅扩展数据图、7 幅补充图 + 5 个补充表、11 幅补充图（这 11 幅被正文引用 3–13 次）。根因是"板块 6 是唯一少写也不显得不完整的板块"——目录里图标题都在，看着是齐的。**唯一有效的手段是机械校验，不是自我提醒。**
20. **补充图命名体系必须识别全（硬性）**：同一件事在不同期刊有四种写法，漏认任何一种都会导致漏解析：
    - `Figure S1`（S 编号，最常见）
    - `Extended Data Fig. 1`（Nature 系，**纯数字不是 S**）
    - `Supplementary Fig. 1`（纯数字，部分期刊用）
    - 带面板后缀：`Figure S1A`、`S12B`（编号后直接跟字母，正则必须允许）
    **稿件板块 6 引用图号时，也必须用原文的命名体系**，不得把 `Extended Data Fig. 1` 改写成"补充图 1"——那会让门禁与人工都无法对照。
21. **缺陷台账当场登记（硬性元规则）**：**只要出现一项——我的错误或别人的优点——立刻在 `outputs/缺陷台账_持续累积.md` 新增一条**，编号顺延，带可核查证据。
    - **禁止行为**：把多条错误收敛成一句"共同结论"；只登记重复出现的、漏掉只出现一次的；只记缺点不记优点（我的优点也要登记，编号 `G`）。
    - **禁止行为**：用"共同根因"遮盖条目明细——根因分析可以另附，但不能替代逐条登记。
    - **本条适用于所有复盘、对比、自查类任务**，不限于文献精读。
22. **三个固定栏位不许省（硬性）**：
    - **板块 5「关键节点」必须穷举式盘点**：凡原文出现具体日期/时间刻度的事件一律列出，**不做取舍**。实测教训：我曾只挑 2 个（72 字），对方穷举 6 个（149 字）。判断会漏，盘点不会。
    - **板块 10「可引用金句」≥3 条**：格式 `"<英文原文>"（<中译>）—— <位置/页码>`。实测教训：我曾整块缺失，导致该板块比对方少 167 字；可直接引用的原文句是精读产物里使用频率最高的部分。
    - **板块 8 必查「命名 / 概念提炼创新」**：作者是否新造术语或统一命名？"命名"本身就是学术贡献，必须单列一条。实测教训：我曾把 PEI 只当内容点，漏掉这个维度。
23. **赢了也要查"是否因问题触发条件不存在"（硬性）**：某篇表现好时，**必须主动判断是不是原文结构恰好绕开了我的缺陷**，并在交付里写明。
    - 实测教训：COVID-19 篇我全面超出（+25% 字数），真实原因是**该篇原文只有 2 图 0 补充图**，恰好绕开我最大的缺陷（补充图零解析）。**若不主动点破，会误以为问题已解决。**
24. **"写了规则"不等于"修好了"——必须双向回归验证（硬性元规则）**：任何新增/修改的红线、脚本、规格，**在标"已修"之前必须完成双向测试**，拿到可复现的输出（脚本退出码 / 报告段落 / 前后对比），否则状态只能标"未验证"。
    - **方向一（假阴性测试）**：对**全部历史真实稿件**重跑，确认旧缺陷仍被抓住、且**没有漏报**。
    - **方向二（假阳性测试）**：**构造一份完全合规的稿**，确认它**能通过**（退出码 0）。**只测方向一是不够的**——门禁过严会把正确的稿判死，逼我为了过闸而灌水。
    - 实测教训：红线 14（补充图逐条解析）早已写明，但连续四次实际产出**全部漏**。把"写了规则"当成了"修好了"，**这是假修复**。
- 实测教训：`图数审计.py` 建成当天被判"已修"，一跑真实数据就发现**两个漏报 bug**：① 漏认列表形式（3 幅补图只报 1 幅）；② 被 `Extended Data Fig. 1–7` 的**声明句**骗到，把未解析的图判为已覆盖（报"缺 5 幅"而实际"7 幅全漏"）。同日还通过假阳性测试发现**两个过严 bug**：③ 金句栏按"金句"二字计数，小标题只算 1 条；④ 声明"N 幅主图"被拿去和**全部条目**总数比较，把合规稿判死。
    - **结论：门禁自己也会错，所以门禁必须双向测。** 每次改脚本，两个方向都要跑。
25. **同一缺陷每次出现都单独计数（硬性）**：一个缺陷在第二篇、第三篇再犯时，**不是"已知问题"，而是新条目**，必须新编号登记，并在条目里写"第 N 次"。
    - 为什么：把复发当成"已知"会让复发隐形——"补充图零解析"因为被当成同一个问题，四次复发只记了一条，掩盖了规则完全失效的事实。
26. **四个视角自查（硬性元规则，适用于本技能自己的全部产出物——脚本、模板、规格、报告）**：任何交付前，逐条过这四个视角，**不得跳过**：
    - **① 诚实性**：有没有"看起来成功"的假成功？——**静默产出的空壳**（如空输入生成 4.9 KB 空页面）、**在无证据的情况下断言**（如剥离逻辑误删真解析后凭空报"零解析"）、**结论措辞超出证据**（如把"未触发可机检项"写成"合格"）。**不诚实的失败方式有两种：报错、和静默给假成品；后者更坏。**
    - **② bug 风险**：有没有把正确输入判错的路径？改动一个正则/护栏时，必须同时问"它会不会把**正常的**输入也拦掉"。
    - **③ 未经核实的结论**：所有"已修／通过／未发现异常"必须附**可复现证据**（退出码、实测输出、前后对比）。拿不到证据的，状态只能标"未验证"，不许标"已修"。
    - **④ 重复卡死**：有没有可能无限循环 / 指数级变慢 / 反复重试同一动作？审查一切 `while`、嵌套循环、`re.sub` 递归展开。已知实例：`图数审计.py` 的列表展开曾无限扩张；`数字校验.py` 的 `find_integer_conflicts()` 曾是 O(n²)。**对复杂度可疑处，一律加"规模阈值 + 墙钟预算"双护栏，超限即降级并显式声明结果不完整。**
    - **取舍原则（必须写进代码注释）**：当"漏报"与"误报"无法同时消除时，**选漏报**——误报会把正确的东西判死、并制造伪造证据；漏报只是少发现一个问题。但**无论选哪边，都必须在输出里声明边界**，不许让读者以为已经全查过了。
    - **第四轮四视角重审的实证**：① 不诚实 3 项（X34 一级标题图条目全漏认→静默给假成品 / X34-b 报告自相矛盾打印全 OK / X34-c 主图零解析只进 warnings）；② bug 风险 3 项（X35 假阳性致稿永不通过 / X36 章节号缺词边界 `7` 吞 `70` / X36-b 同一事实两套口径）；③ 结论超证据 2 项（X37 把正常通过说成"漏报！" / X37-b 单篇复跑就宣布通过）；④ 卡死 **0 项**（压测通过）。
    - **四视角中"卡死"一项要压测才算查过**：本轮以 10 万次密集计数（0.26s）、200 万字符单行（0.59s）、6 篇真实稿端到端（最长 0.85s）、全文 `except ... pass` 扫描（0 处）四组实测支撑"无风险"结论。**压测过的"没问题"和没压测过的"没问题"不是一回事。**
27. **唯一实现原则（硬性）**：凡"同一事实在脚本里有两处实现"，改一处必留另一处。**修改前先 `grep` 出全部实现路径，改完再 grep 一次确认清零**；关键计数必须收敛为唯一函数。
    - 为什么：X21 修在 `_split_entry_blocks()`，但 `audit()` 里另有独立的内联 `findall` 计数 → "断言过了、审计报告仍报 3 条"。**同一事实两处实现，等于修了一半。**
28. **诚实声明不得被计为缺陷（硬性）**：稿件里"如实声明 0 图 / 0 表 / 未读到"的收尾块，**不得**被当成图条目或缺陷证据。
    - 为什么：`## 图表 3：全文表格盘点（★ 如实标注）` 曾被算成第 3 个图条目 → 6 条七栏齐全度全部误报"缺"。**门禁必须鼓励诚实，不许惩罚诚实**；一个惩罚"如实声明无表"的门禁，最终会训练出"少写声明块蒙混"的行为，比没有门禁更坏。
29. **专有名词禁止音译回中文（硬性，最高优先）**：**人名、机构名、产品名、试剂盒名、软件名、基因/蛋白的官方命名**一律**照抄原文**，不许"翻译"。
    - **核心规则**：**原文没有汉字 → 稿件里就不许有汉字的人名。零豁免。**
    - **绝对不许做的事**：
      ① 由英文名拼音倒推汉字（`Samplefull Zhang` → "张甲" 这类）；
      ② **拿邮箱当依据**——**邮箱推不出汉字**，同一串拼音对应多种汉字写法，仍是猜；
      ③ **靠"加一句来源说明"绕过**（写成 `英文名（中文名，单位；邮箱）　← 中文名由邮箱得出`）——加说明不改变"汉字是猜的"这个事实。
    - **无任何自然人姓名豁免**：本技能不记录、不比对使用者或任何人的真实姓名（详见「隐私边界」一节）。
    - **正确写法**：只留英文原名，单位与邮箱照录。
      例：`Li-jun Di（某大学；邮箱 xxx@example.edu）`（不带任何中文名）。
    - **实测教训（两轮指出）**：
      第一轮曾在五篇稿里**批量编造 15 个中文人名**，被截图质问"**不会翻译就别翻译，人名你还翻译上了**"；
      第二轮"补救"成加邮箱说明的版本，再次被否决："**你要是不知道，统一别翻译好不**"。
      **两轮加起来说明一件事：不是"偶尔翻错"，而是有一个"见到英文名就想配中文"的坏习惯。**
    - **为什么这条是最高优先**：人名错误会**直接损害学术信誉**（写错合作者/通讯作者的名字），且在求职材料、致谢、引用里会被人一眼看出。**宁可只写英文名显得"不够本地化"，也绝不许写错。**
    - **机器门禁**：`scripts/人名审计.py`（见 Phase 3 第一步），退出码 1 一律不许交付。

30. **说人话——中文读一遍必须能懂（硬性，适用于所有小标题与正文）**：稿子是给中文读者读的，**"忠于原文"不等于"照抄原文词序"**。
    - **判断标准**：**一个没读过原文的中文读者，能否一遍读懂这句话在说什么。** 读不懂就是错，不管它多"对应原文"。
    - **禁止做的事**：
      ① **把英文术语硬塞进中文动词位**。反例：`N 基因签名……可分层生存与铂类敏感性`——`分层 (stratify)` 在中文里是方法论名词，塞进动词位后整句空转；
      ② **并列语义不对称的成分**。反例同上一句："生存"是被分层的对象，"铂类敏感性"是分组后被比较的**指标**，两者不在同一逻辑层级，不能并列在同一次"分层"下；
      ③ **生硬直译英文复合名词**。如 `基因签名 (gene signature)` → 中文写"这组基因 / 这 443 个基因"更顺。
    - **正确写法（实测改写）**：
      反例：`N 基因签名在某公共队列中可分层生存与药物敏感性`
      改写：`这 N 个基因能按表达谱把该队列患者分成 6 组，各组生存期与药物敏感性都不同`
      —— 改写后**信息量不减**（N 个、队列、分成 6 组、生存与药敏两个差异），但中文读者一遍就懂。
    - **为什么这条必须写进来（实测教训）**：被指读不懂时问"**这句话翻译的啥玩意，人能看懂吗**"。根因是把 Fig. 3 图注的英文链路（consensus clustering → survival analysis）**直译而未转成中文语序**。
      **此前所有复盘全在盯"漏没漏图、数字对不对"，表达可读性从未进过自查清单**——这是盲区。
    - **连带检查**：被点出一处生硬措辞时，**必须全篇 grep 同类措辞一次**，不许只改被指的那一句（实测该措辞在标题与板块 6 各出现一次，只改标题会漏）。

31. **图条目识别口径必须显式写出（硬性）**：识别口径为 `#`~`####` 级标题 + `图表 N` / `Figure N` / `图 N` 前缀；含"盘点 / 声明 / 无表 / 合计"等收尾语义词的标题**不算**图条目。
    - **口径必须打印进审计报告**，因为"识别不到"和"没问题"在输出上长得一模一样——不写出边界，读者无法自查是否被漏认。
    - 实测教训（X34）：某篇 8 个图条目写成一级标题 `# 图表 N`，旧正则只认 `#{2,4}` → 条目数 0 → 七栏核验**静默跳过**、报告反而全 OK。**放宽到 `#{1,4}` 后**才正确认出 26 条。
32. **测试的期望态必须与事实同步（硬性）**：期望态（`pass` / `violate`）写死在配对清单里，**事实变了它不会自己变，只会变成假警报**。
    - **事实变了，改期望态不算"放松测试"；不改，才是让测试说谎。** 假警报会训练人忽略该方向的告警——狼来了，真漏报时会被一起无视。
    - 实测教训（X35-b）：某篇修好后清单仍写 `violate`，回归测试每天报一行假的"**漏报！**"。改期望态时**必须在清单里留痕写明为什么改**，防止后人误改回去。
    - **连带要求**：凡改动脚本，**必须整跑回归测试**（含常驻负例 fixture），单篇复跑通过**不构成**证据（X37-b）。

33. **视觉参数必须机器冻结（硬性）**：版式 / 字体 / 颜色 / 排版参数一律以 `scripts/视觉规格基线.txt` 为唯一真源，交付前必须跑 `scripts/视觉规格门禁.py`。
    - **为什么写这条**：曾被直接问"这些参数是否已固定、能否保证每次不变"。核实后发现——**它们只是"恰好一致"，没有任何机器在守**：5 个门禁脚本对 CSS/字号/颜色的校验**命中 0 处**。
    - **"恰好一致"≠"被强制一致"**：前者下次改动就会破，且**无人报警**；后者才叫固定。凡声称"格式固定"却没有机器校验的，都是前一种。
    - **改样式的唯一流程**：① 改 `templates/精读转网页.py` → ② `python scripts/视觉规格门禁.py --update-baseline` → ③ 同步 SKILL.md 的「详情页视觉规格」表。**三处缺一即为规则与实现脱节。**
    - **不许只看文档声明就相信格式已固定**——本技能已有定论："文字规则拦不住，机械校验才拦得住"。**凡"固定/保证/一定"这类断言，必须能指到一个会返回非零退出码的脚本。**

34. **技能不得记录任何个人信息（硬性，上架合规要求）**：本技能**只做文献精读**，不得采集、存储、传递任何个人信息。
    - **不许有输入个人身份的地方**：不询问使用者的姓名 / 别名 / 单位 / 邮箱 / 账号，不设"使用前填一次"之类的身份配置。
    - **不许做身份相关推断**：不判断使用者在作者列表中的位次，不做"对本人的用法 / 与使用者主线的衔接"这类需要知道使用者是谁的个性化小节。
    - **不许在技能自有文件里留痕**：清单、注释、示例、自测用例、版本元数据里，不得出现任何**真实自然人姓名**（中英文）、邮箱、私人工号或单位内部信息。`author` 之类的元数据字段写的是**品牌署名**（见下条），不是个人姓名。
    - **`author` 字段写"花名"，不是人名（2026-09-21 纠正）**：本技能的 `author` 取值为**专家花名**——它是**对外品牌标识**（用于头像、吉祥物、品牌记忆点），**不替代正式专家名**，**不是自然人姓名**。因此 `author: 琅嬛` **不构成个人信息**，门禁**不得**把它判为违规。
      - **教训**：不要"看到一串中文就当成姓名"。`隐私审计.py` 自己已声明能力边界——**"不识别某串汉字是否为真实人名"**；脚本既然判不了，就不许把"字段有值"等同于"这是个人信息"。
      - **门禁口径（已修）**：`author` 字段值属于**已登记品牌花名白名单**时放行；仅在**值形如真人姓名**（2–4 汉字，或 `Firstname Lastname` 形态英文名）时才告警。**实测**：`author: 张叁` → 拦（EXIT=1）；`author: 琅嬛` / `author: 知微` → 放行；`author: Jane Doe` → 拦。
    - **示例一律用明显虚构占位**：`Firstname Lastname`、`xxx@example.edu`、`某大学`。
    - **产物里的作者信息来自原文**：只照录原文形态，不做音译、不做回译、不做推测补全（与红线 29 一致）。
    - **机器门禁**：`scripts/隐私审计.py`，退出码 1 一律不许交付。
    - **为什么写这条**：技能要上架给他人使用，工具本身不该背任何人的个人信息；且让工具去认使用者的身份，对"把文献读懂"这件事毫无必要——**它只增加泄露面，不增加精读质量**。之前为做"个性化"引入的身份配置，是功能上的过度设计，已整体移除。
35. **两个交付物固定、不许随意改（硬性，最高优先的交付契约）**：客户给一篇文章，固定交付**这两个文件**，缺一即违规、不增、不减、不改名：
    - ① **`科研文献分类导航库.html`（库仪表盘）**：文章入库归档后必须重建/更新，作为交付物交给客户。
    - ② **`文献精读_<第一作者姓氏>_<年份>_<关键词>.html`（精读网页，必做）**：文件名按**文章信息**（作者 / 年份 / 关键词）生成，**绝不用 `reading.html` 这类内部名**当客户产物名。
    - **`reading.md` 不算交付物**：它是内部母版，只存 entry 目录留底，**不呈现给客户、不发给客户、不计入交付清单**。
    - **只做到一半=违规**：只入库不出精读 HTML、或只出精读不重建仪表盘，都算未完成交付。不许因"顺手优化 / 这次特殊 / 我觉得该加"增删其一、改命名或改分工。
    - **【强制】机器门禁 —— 退出码是唯一判据**：交付前必须跑（判据是"交付物在不在"，不是"命令报没报错"）：
      ```bash
      python <科研文献分类导航库>/scripts/交付门禁.py --id <条目标识>
      ```
      **退出码 0** = 两个交付物齐全 → 才许宣告完成；**退出码 1** = 缺交付物 → **禁止交付**，补齐后重跑到 0。
      回报必须贴出「两条 OK/FAIL + 字节数 + 退出码」；只写"已完成"不带退出码，等同未核验。
      实测自证（2026-09-21）：完整交付的 Neospora 条目 → 退出码 0（精读 HTML 61559 字节 + 仪表盘 592706 字节）；人为造的"只收文"半截状态 → 退出码 1，打印"只入库不算交付"。
    - **判据纠偏（本条要害）**：**不许把"命令退出码 0"当成"交付完成"**。收文/归档跑通 ≠ 交付物存在（实测 2026-09-21 教训：只跑了收文就宣称验证通过，而客户要的精读网页根本不存在）。验的是**东西在不在**，不是**流程跑没跑**。
    - **为什么写这条（实测教训）**：① 曾把六篇产物统一命名为 `reading.html`（内部名）直接当客户文件，被指出"精读产物是给 html 的，但要**以文章信息命名**，不是 reading 命名；`reading.md` 只存到文件夹、不要呈现给客户"。② 曾把红线误写成"两件套 = reading.md + HTML"，把内部母版当成交付物；2026-09-21 用户明确纠正：**必须交付的是 `科研文献分类导航库.html` 和 `文献精读_<第一作者姓氏>_<年份>_<关键词>.html`**。同日实测：验证一篇文章只跑收文就交付仪表盘，精读 HTML 没做——半截交付，同样违规。
    - **【2026-09-21 三遍自查补强】交付门禁三处漏洞已修（每条都附回测退出码）**：
      | 漏洞 | 原判据 | 错在哪（实测） | 现判据 | 回测 |
      |---|---|---|---|---|
      | **子串假 OK** | `pid in 仪表盘全文` | 条目 `A100` 未收录，但库内 `A1000` 已收录 → `"A100" in txt` 因**子串**恒真 → 未重建的仪表盘被判通过 | 解析仪表盘内嵌 `const DATA` 的 JSON，取 `entries[].id` 做**精确相等**；无 JSON 时退化为带引号精确匹配并 WARN | `A100` 不在盘 → **1**（原 0）；`A1000` 在盘 → 0 |

      | ~~文件名碰撞~~ **（已回退，见下）** | 文件名 = 姓氏+年份+前两方向词 | 同作者+同年+同方向的三篇**不同**文章会得到相同文件名 | **不改名**：条目各在独立目录，跨条目同名覆盖在本库结构里不会发生 | 全库 8 篇命名 **8/8 一致** |
      - **⚠️「文件名加 pid」这个修法已作废（2026-09-21 二次回退，附实测代价）**：曾一度在文件名尾部追加 pid 以求唯一，打包前复算发现**代价大于收益**——

        ③ **结构上本无此风险**：每个条目在库里是**独立目录**，精读网页各自躺在自己的 entry 目录内，根本不在同一目录下。用户已明确指出"各存各的文件夹，为什么要考虑重名？"——**用户是对的，我自设了"平铺到同一目录"的伪场景**。

      - **仍未处置的边界（诚实声明）**：**"先精读、后入库"的顺序（红线 2）没有任何机器强制**。实测：单独跑 `收文` → **EXIT=0** 并打印"收文成功"；只有事后补跑 `交付门禁` 才会 EXIT=1 拦住。即"**结果**被守住了，**顺序**没有"——红线 2 目前是**纯文档约束**。是否补机器门禁待用户决定，**不自作主张加功能**。
36. **精读网页必须标出影响因子；解析 IF 必须早于生成 HTML（硬性）**：精读一篇文献时，**页头必须能看到这篇的影响因子**（`IF x.x · 分区 · 期刊名`），且导航库支持按 IF 筛选。

      **"归档成功、退出码 0、但网页上永远没有 IF"**。这是典型的"每步都成功、整体没效果"。

      使 IF 徽标对**既有旧条目**同样生效（无需重跑精读、不改动 `reading.md`）。
    - **改样式后必须三处同步**：改 `templates/精读转网页.py` → `--update-baseline` → 同步本文件「影响因子徽标」表。
    - **实测自证（2026-09-21）**：全库 8 篇逐一回填 → **8/8 渲染出 IF 徽标**、归档退出码全 0；

    - **为什么写这条**：IF 是判断一篇文献"值不值得精读"的第一道筛子，也是导航库分档的依据。
      此前 IF 只写进了 `meta.json` 和数据库（`litlib.py 影响因子` 能筛、仪表盘能筛），**唯独最该显示的客户交付物上没有**——
      "算出来了但没渲染出来"不算做完了。

## 缺陷台账（常驻机制，最高优先的元规则）

### 规则：只要出现一项，立刻登记一条

**用户 2026-09-20 明确要求："只要是你犯的错误，别人的优点，每出现一项都要加进去。"**

这不是"复盘时才整理"，而是**运行中的持续登记**：

| 触发事件 | 必须做的动作 |
|---|---|
| 我犯了一个新错误（任何性质：漏解析、数字错、格式缺、流程错、撒谎式表述） | **当场**在台账新增一条 `M/F/C/P/E` 编号，写清「错在哪 + 可核查证据 + 状态」 |
| 我看到别人（第三方产出、同行、用户）做对了一件我没做的事 | **当场**新增一条 `S/V/R` 编号，写清「对方的做法 + 我的状态 + 差距量化」 |
| 我做对了一件对方没做的事 | **当场**新增一条 `G` 编号（优点也要登记，不许只记缺点） |
| 我在"复盘行为本身"上犯了错（收敛成结论、只盯同一缺点、单篇对标…） | **当场**新增一条 `X` 编号 |

### 台账三条铁律

1. **只增不减**：编号顺延，已登记的条目不删除、不合并、不"收敛"。哪怕三条说的是同一件事，也各占一条编号。
2. **每条必带证据**：文件路径 + 行号 / 命令输出 / 原文引用。**凭记忆写的不算**，没证据的条目一律标"未核实"。
3. **不许用"共同根因"遮盖条目**：可以另附根因分析，但**根因不是替代品**——31 条错误不能因为"根因只有一个"就缩成 1 条。

### 台账位置

默认写在当前工作区 `outputs/缺陷台账_持续累积.md`。跨项目通用时写在 `~/.workbuddy/MEMORY.md` 的对应小节。

### 为什么要有这个机制（实测教训，必须记住）

- 我曾把三次对比复盘**揉成一句"三篇都缺补充图"**就交货，被用户严厉批评："谁让你总结共同结论了？你要把你所有犯过的错误，别人有的优点都要总结下来，谁让你一直看着相同的缺点了。"——**收敛是偷懒，不是提炼。**
- 我曾"反复盯着同一个缺点"（补充图），导致另外 30 条错误、19 条对方优点、11 条我的优点**全部没被记录**，直接损失了整轮对比的价值。
- **只记"重复出现的"是错的**：出现一次的错误也要记，因为它可能只被触发一次就造成事故。

### 左侧目录跟随滚动（2026-09-20 实现）

起因：「右边的滑动。左边的导航键也要滚动到相应的位置，两边遥相呼应」。

- **关键点：目录本身是独立可滚动容器**（`nav{max-height:calc(100vh-116px);overflow:auto}`），
  所以要滚的是 **`nav.scrollTop`**，不是 `window`——写成 `window.scrollTo` 或 `scrollIntoView`
  会把整个页面带走，反而更糟。
- **章节集合必须写成 `main section[id], main h2[id]`**（不是 `main h1`，见下方坑 2）。
- **交付前必须用真实浏览器打开确认**（见下方坑 3：mock 会给出假通过）。
- 留 **28% 上下余量**（`pad`），高亮项不做"贴边跳"，而是滚到舒适位置。
- **点击目录后的锁定（`lockUntil`，700ms）**：点目录会触发正文平滑滚动，途中 `scroll` 事件
  仍会触发，若不锁定，高亮会被"半路经过"的章节抢走。锁定期内 `spy()` **直接 return**，
  既不改高亮、也不滚目录。
- **`curId` 去重**：章节没变就不重复写 DOM、不重复滚动，避免每帧抖动。
- **机器门禁**：`scripts/导航测试.py`（**真实浏览器**，用本机 Edge/Chrome，零额外下载）。
  改任何导航逻辑后 **必须跑**：
  ```
  python scripts/导航测试.py            # 默认扫 outputs/ 下全部 文献精读_*.html
  ```
  三组断言：① 锚点与目录项一一对应、无空 id；② 滚动时高亮确实在变、目录确实在滚；
  ③ 点击目录能跳转并高亮。实测 6 份全通过。

#### 这里踩过两个坑，都必须记住（2026-09-20，两次收到"根本没实现"的反馈）

**坑 1：`const top` 与浏览器内置 `window.top` 冲突，整个脚本从解析阶段就挂掉。**
```js
const top=document.getElementById('top');   // ✗ SyntaxError: Identifier 'top' has already been declared
```
后果不是"某个功能失效"，而是**整个 `<script>` 一行都不执行**——滚动监听、高亮、目录跟随、
回到顶部按钮**全部失效**，而且**页面不弹任何提示**，肉眼看就是"左边完全没反应"。
- 修法：变量改名（现用 `toTopBtn`），并加 `if(toTopBtn){...}` 守卫。
- **通用戒律**：浏览器里有一批**内置全局属性名不能用作 `const/let` 变量名**，
  典型的有 `top`、`self`、`name`、`length`、`status`、`origin`、`parent`、`location`、`history`。
  取名一律加业务前缀（`toTopBtn` 而非 `top`、`navEl` 而非 `nav`）。

**坑 2：章节锚点误用 `main h1`，而 `h1` 没有 `id`。**
```js
const secs=[...document.querySelectorAll('main h1, main h2[id]')];   // ✗ h1 的 id 是空串
```
板块锚点挂在外层 `<section id="sec-N">` 上，**`h1` 自己没有 id**。
于是 `cur.id === ''`，与任何目录项都对不上，高亮**定格不动**。
- 修法：`document.querySelectorAll('main section[id], main h2[id]')`。

**坑 3（元教训，比前两个更重要）：mock 测试给出过 14/14 的假通过。**
我先前写了个 Node + mock DOM 的导航测试，**全绿**，但页面在真实浏览器里
**一行 JS 都没跑**——因为 mock 环境里没有 `window.top`，测不出坑 1。
> **导航 / 布局 / CSS / 事件这类逻辑，mock 通过不算通过，必须真实渲染 + 真实滚动。**
> 该 mock 测试已删除，替换为 `导航测试.py`（Playwright + 本机 Edge，真实渲染）。

### ⚠️ 平台卡的是"解压后"，不是 zip 大小（2026-09-21 被驳回）

**我踩的坑**：自检写成"zip 体积 <3MB"，zip 只有 0.89MB 就判通过 → 上传被驳回：

### 影响因子表为什么必须压缩存储

`scripts/journal_if_map.json` 是 22,643 条期刊数据，**对象化 JSON**（每条重复写 8 个键名）解压后 **4.06MB**，
单它就顶穿 3MB 上限（整包解压后 4.78MB）。

**处置**：改存「列定义 + 行数组 + 低基数字段字典编码」→ **1.94MB（省 53%）**，**22,643 条一条不丢**。
转换脚本：`scripts/压缩影响因子表.py`（带**无损校验**，校验不过拒绝写盘）。

```bash
python scripts/压缩影响因子表.py                 # 演练（不写盘）
python scripts/压缩影响因子表.py --write          # 真正替换
python scripts/压缩影响因子表.py --verify-only    # 只校验现有表可解码
```

**两种格式都读得懂**：`jcr_helper._decode()` 同时兼容「旧对象格式」与「新列式格式」，
所以旧库、旧环境、以及用户自己换回原表的场景都不受影响。

**★ 压缩时必须保住"三态"（这是最容易压丢的东西）**：
原始表里字段有三种状态，混同任何两种都会改变调用方行为——
| 状态 | 例 | 编码 |
|---|---|---|
| 有值 | `"jcr_quartile": "Q1"` | 字典下标 |
| **键在、值为 null** | `"if": null`（668 条无 IF 的人文期刊） | 哨兵 `-2` |
| **键整个缺失** | 无 `cas_big_class` 字段（1,303 条） | 哨兵 `-1` |
把"键在但值为 null"当成"键缺失"，会让 `info["if"]` 从**取到 None** 变成 **KeyError**。
### 打包前必做的一件事（2026-09-21 血泪）

**"无害"不是可以自称的结论，是需要实测的命题。** 该修复已回退。

# 文献库（入库 / 检索 / 仪表盘）

> 本技能自带文献库能力（原先的「科研文献分类导航库」已并入）。存储根默认 `~/Documents/科研文献库/`，可用环境变量 `LITLIB_ROOT` 覆盖。
> 运行方式：`python <本技能目录>/scripts/litlib.py <命令> [参数]`（命令与参数均为中文）。

### 定位
- 独立本地库，单一数据源，不依赖桌面日记、不碰任何现有生产系统。
- 技术栈：Python 标准库 + SQLite(FTS5) + 纯前端 HTML，**零第三方依赖**。
- 存储根：`~/Documents/科研文献库/`（可用环境变量 `LITLIB_ROOT` 覆盖）。
- 每篇一个 entry 目录，按「保留 / 不收藏 / 未分类」归入对应子文件夹：
  ```
  保留/<标识>/source.<ext>                    原文（复制进库，保留原始扩展名）
  保留/<标识>/reading.md                      11 板块精读 Markdown 母版（内部留存，不直接呈现给客户）
  保留/<标识>/文献精读_作者_年份_关键词.html   精读网页版（客户可见，双击即看，可分发）
  保留/<标识>/meta.json                       结构化元数据
  ```
  （不收藏/未分类 结构相同；用户源文件只复制不移动，绝不碰原始存放位置）

### 何时使用
- **客户给一篇文章要精读（默认主流程）**：`精读`（先）→ `收文` → `归档`（后两步连续执行，中间不停）→ 交两件
- 用户上传 PDF/Word **只要入库、明确说了不精读** → `收文`；此时必须说明这是**未精读的空条目**，不是交付物
- 精读（科研文献精读剖析助手）完成后 → `归档` 补全 → `判定 --类别` 归类
- “找外泌体/某作者/某机构/某期刊相关文献” → `检索` / 维度命令
- “统计一下我的文献库” → `统计` 或打开 `科研文献分类导航库.html`
- 发现某篇归类错了 / 文件被手动挪过 → `修复` 让 DB 重新对齐文件系统

### 运行方式
所有命令经 Bash 调用受管 Python 运行**本技能自带的** `scripts/litlib.py`（命令与参数均为中文）：
```
python <本技能目录>/scripts/litlib.py <命令> [参数]
```
> 文献库根目录可用环境变量 `LITLIB_ROOT` 指定；未设置时取脚本内默认值。

### 命令清单（全部为中文）

### 分类状态（保留 / 不收藏 / 未分类）
- 每篇文献归属三个物理子文件夹之一，状态即文件夹位置，持久化在 SQLite `entries.folder`/`keep` 列与 `meta.json` 的 `folder`/`keep` 字段（三者同步，文件系统为真实来源）。
- 规则（用户指定）：**逐篇手动判定**。精读自动收文时一律先归「未分类」，由你在仪表盘点按钮或命令行 `判定` 决定。
- `不收藏` 仍完整保留源文件+精读+元数据，仅仪表盘默认隐藏；点导航「分类 → 不收藏」或「显示不收藏」开关可查看/恢复。符合“绝不丢失条目”。
- 仪表盘按钮：每张卡片与详情页均有「保留 / 不收藏 / 未分类」三按钮。点选仅在浏览器记录选择（file:// 下存 localStorage，纯本地查看，零基础设施）。
- **把选择写回磁盘（推荐路径，零 bat）**：在仪表盘点「导出分类决策」→ 浏览器下载 `litlib_decisions.json` → 把该文件**丢进 WorkBuddy 对话框** → AI 读取后运行 `应用决策` 命令，整批一次性搬文件夹 + 同步 DB/meta + 重建仪表盘。**完全离线、不依赖任何常驻进程、重启无影响、最稳**。
- 「服务」实时模式（不推荐）：需先 `服务` 再开 `http://127.0.0.1:8788/科研文献分类导航库.html`，按钮才直接搬文件；常驻进程易挂、重启不自愈，已降级为可选便捷通道，非必需。

### 入库与归类流程（顺序铁律：先精读、后入库；严禁停在收文）

1. **精读优先**：先用「科研文献精读剖析助手」精读产出 11 板块 `reading.md`（内部母版，不直接呈现给客户）。**精读只读 PDF，不依赖库**，所以必须排在第一步。
2. `收文 <源文件>` → 源文件复制进 `未分类/<标识>/source.<ext>`，建 meta.json 骨架；Agent 按精读内容把分类字段（第一作者/年份/期刊/研究方向/方法/通路等）填进 `未分类/<标识>/meta.json`。
3. `归档 --id <标识> --reading <reading.md>` → 复制 reading、**自动生成客户可见的 `文献精读_作者_年份_关键词.html`**、JCR 匹配影响因子、入 SQLite+FTS5、重建仪表盘。
4. 用户在仪表盘点「保留 / 不收藏 / 未分类」按钮，或命令行 `判定 --类别` → `未分类/<标识>/` 整文件夹搬移到目标子目录，DB+meta 同步。

> **为什么必须是"先精读、后入库"**：`收文` 单独执行只会在库里留下一个**没有任何精读产物的空条目**，那是未完成状态，不是交付物。先精读能保证每一步手上都有实质内容，从源头杜绝空条目。
>
> **实测教训（2026-09-21）**：先跑 `收文` 就宣称"验证通过"，而客户要的精读网页根本不存在——半截交付，用户当场发火。根因就是顺序反了 + 把"命令跑通"当"交付完成"。
>
> **收文后必须紧跟归档**：`收文` 与 `归档` 应连续执行，中间不许中断、不许把 `收文` 的结果当成进度汇报给客户。交付前必跑 `scripts/交付门禁.py --id <标识>`，**退出码 0** 才许宣告完成。

### 仪表盘（科研文献分类导航库.html）
单文件、零依赖、离线双击。含：总数/各分类计数/平均影响因子卡片、作者频次、机构分布、研究方向/方法/模型/通路/期刊/年份分布、标签云、可筛选可排序的文献清单（行内 原文/精读 HTML file:// 链接）；左栏导航按维度分组（含「分类」分组可点筛选 保留/不收藏/未分类），卡片与详情页均带「保留 / 不收藏 / 未分类」三按钮，详情页额外提供「打开精读 HTML」按钮直达客户可见的精读网页。

> 仪表盘 file:// 直接双击打开即可浏览与分类点选（按钮仅存浏览器 localStorage）。**真正写回磁盘**：在仪表盘点「导出分类决策」下载 JSON → 丢进 WorkBuddy 对话框 → 让 AI 跑 `应用决策` 命令，整批搬文件夹并重建仪表盘。无需起任何服务、无 bat。

### 与桌面日记衔接
完全独立。若日后要做桌面日记卡片：由本库提供精简片段，桌面日记侧自行读取渲染，本库不主动写桌面日记。
