# SCI论文与真实文献研究写作

## 目标

把研究问题、可核验文献、证据矩阵和论文初稿连接起来。默认采用“证据先行、分段写作、逐条审计”的方式，不把模型记忆、搜索摘要或合理猜测伪装成真实文献、实验结果或研究结论。

## 绝对约束

- 不凭记忆编造参考文献、DOI、PMID、作者、期刊、年份、数据或实验结果。
- 没有可追溯来源的文献只能标记为“待核验”，不能进入正式参考文献表。
- “论文真实存在”和“论文支持某个论断”必须分别检查。
- 不把相关性写成因果性，不把动物、体外、单中心或小样本结果无条件外推到其他场景。
- 原始研究没有提供真实数据时，只能生成研究设计、分析计划和结果占位符，不能代写Results中的事实。
- 对存在相反结果的主题，应主动寻找并呈现相反证据，而不是只收集支持性文献。
- 论文初稿必须标出未经核验的内容、缺失的原始数据和需要作者确认的判断。

## 工作模式

根据用户请求选择一个或多个模式：

1. **研究设计模式**：明确研究问题、论文类型、变量、结局指标、目标期刊和检索范围。
2. **文献检索模式**：设计可复现检索式，收集候选文献并记录来源和日期。
3. **文献核验模式**：核对DOI、PMID、出版社或数据库记录及全文证据。
4. **综述综合模式**：按主题、方法、证据强度、争议和研究空白组织文献。
5. **论文初稿模式**：先列论断和证据，再分章节生成初稿。
6. **引用审计模式**：检查文献真实性、引用支持性、过度推断、遗漏反方证据和格式。
7. **系统综述模式**：执行问题定义、纳入排除标准、筛选、数据提取、偏倚风险和PRISMA式记录。

## 标准流程

### 1. 先确认研究边界

缺少关键信息时，先询问最少但必要的问题：

- 主题和具体研究问题
- 原始研究、叙述性综述、系统综述还是Meta分析
- 学科、研究对象和主要变量
- 目标期刊或期刊级别
- 中文、英文或双语
- 文献时间范围和希望纳入的研究类型
- 是否有自己的数据、实验结果或已收集的文献

不要在研究问题不清楚时直接生成长篇正文。

### 2. 建立研究文件

对于超过一次回复的任务，在用户指定目录或当前项目的`work/`下建立并持续更新：

- `research_protocol.md`：研究问题、范围、纳入标准、目标期刊和检索策略
- `search_log.md`：数据库、检索式、日期、结果数量和调整记录
- `evidence_matrix.md`：论断、文献、证据位置、证据强度和限制
- `draft.md`：论文或综述初稿
- `citation_audit.md`：文献核验和引用审计结果

如果用户明确指定了其他文件位置，应遵循用户指定位置，不要擅自扩展写入范围。

### 3. 设计检索策略

为每个核心概念建立：

- 主题词、自由词、同义词、缩写
- 研究对象或人群词
- 方法、干预、暴露或技术词
- 结局指标词
- 排除词和时间限制

按数据库或来源分别保存完整检索式。检索时优先使用原始研究、权威综述、指南、官方数据库和出版社页面。检索结果用于发现候选文献，不能仅凭搜索结果摘要写出研究结论。

### 4. 验证文献

为每篇候选文献建立状态：

- `verified`：唯一标识和核心元数据匹配，来源可追溯，可进入正式引用候选表。
- `metadata-verified`：存在可靠记录，但尚未核对全文关键内容。
- `claim-verified`：已读取正文、表格或补充材料，确认能够支持指定论断。
- `needs-check`：信息不完整、来源冲突或全文不可得。
- `excluded`：重复、无关、来源不可靠或无法确认。

核验至少检查：

- 标题、作者和年份
- 期刊或会议名称
- DOI、PMID或其他唯一标识
- 数据库、出版社或期刊官网记录
- 文献类型
- 正文中实际支持的结果和结论

对关键论断优先要求`claim-verified`，而不是只满足`metadata-verified`。

### 5. 建立证据矩阵

不要只生成“文献摘要列表”。至少记录：

| 字段 | 内容 |
|---|---|
| Claim ID | 论断编号 |
| 论断 | 准备写进正文的具体说法 |
| 文献 | 作者、年份、唯一标识 |
| 证据位置 | 摘要、Introduction、Methods、Results、表格、图或补充材料 |
| 证据类型 | 原始研究、综述、指南、数据库或其他 |
| 证据方向 | 支持、反对、混合或无法判断 |
| 证据强度 | 高、中、低或待评估 |
| 适用边界 | 人群、模型、样本、时间和方法限制 |
| 核验状态 | 文献存在性和论断支持性状态 |

如果一个论断没有对应证据，改写为研究问题、研究假设或待验证陈述，不要硬塞进结论。

### 6. 组织综述或论文结构

#### 叙述性综述

按主题或机制组织，不要机械地按作者逐篇罗列。每一节回答：已知什么、证据是否一致、争议在哪里、方法局限是什么、还缺什么。

#### 系统综述或Meta分析

明确PICO/PECO、检索策略、纳入和排除标准、筛选流程、数据提取、偏倚风险、证据综合和研究注册信息。保留排除理由和每一步数量，避免事后编造流程数字。

#### 原始研究论文

使用Title、Abstract、Introduction、Methods、Results、Discussion、Limitations、Conclusion等结构。Methods可根据用户提供的实际方案整理；Results只能使用用户提供或文件中真实存在的数据。

### 7. 生成初步大稿

写作与修改全程遵循「发布会原则」：把论文当作一场学术发布会而非项目总结——只围绕真正成立的优势组织叙事，不写实验流水账，不主动示弱，不替审稿人递刀子；不占优的维度改写比较逻辑或收缩主张，实验只作为论证工具保留。完整规则见`references/press-conference-principle.md`。

采用以下顺序：

1. 先生成文章结构和每节目标。
2. 为每节列出核心论断。
3. 将每个论断绑定到证据矩阵中的文献。
4. 再生成段落和过渡句。
5. 段落完成后立即检查引用是否覆盖论断。
6. 对证据不足之处使用谨慎措辞或插入`[待核验]`、`[需补充数据]`、`[需作者确认]`。

建议使用与证据强度匹配的表述：

- 强证据：`demonstrated`、`consistently reported`、`was confirmed in`
- 中等证据：`suggested`、`was associated with`、`may contribute to`
- 初步证据：`preliminary evidence indicates`、`might`
- 证据不足：`remains unclear`、`has not been established`

不要为了让语言更有说服力而提高结论强度。

### 8. 执行最终审计

输出独立的审计表，至少包括：

- 文献是否真实存在
- 元数据是否准确
- DOI或PMID是否对应正确论文
- 正文论断是否被引用直接或合理地支持
- 是否把综述内容误写成原始研究结果
- 是否把相关性、预测性或机制假设写成因果关系
- 是否遗漏重要反方或不一致证据
- 是否存在无法核验的数字、样本量或效果量
- 正文引用和文末参考文献是否一一对应
- 是否符合目标期刊的引用和结构要求

把问题分为：`必须修正`、`建议修正`、`作者确认`和`可接受风险`。

## 引用文献逐篇精读与教师版 Word 总报告

当用户已有论文初稿或参考文献表，并要求“每篇引用都看懂、提供官方地址、整理成一个可以交给老师的 Word 文档”时，加载 `references/citation-deep-read-and-docx.md`，将其作为独立工作模式执行。

默认输出一个总 Word 文档，不为每篇文献拆成多个交付文件。文档应包含封面、自动目录、文献总览表、逐篇精读章节、官方可点击链接、阅读状态、论文论断—原文证据回链、文献综合比较、待核验事项和访问限制。每篇文献从新页开始，并至少回答研究问题、设计、样本、变量、主要结果、结论边界、局限、与论文引用句的关系和老师可能追问的问题。

时间紧时，所有文献仍须完成统一最低阅读标准；核心论点文献再加深图表、统计量、证据强度和外推边界分析。没有全文不得声称“全文精读”，不能用摘要或标题填充未读的正文内容。Word 文档必须按 `documents` skill 的要求完成渲染、逐页检查和必要修订。
## 多平台文献检索与导航页

当用户要求查找“各大论文平台”、使用 Google Scholar、CNKI、ScienceDirect、Web of Science、Scopus 或老师提供的学术导航页时，加载 `references/multi-database-literature-search.md`。采用“发现入口多元化、正式引用来源收敛”的原则：

1. 先按学科路由选择数据库和关键词组合；
2. 使用 Google Scholar 或用户提供的导航页发现候选文献、相似研究、引用网络和开放版本；
3. 用 Crossref、OpenAlex、PubMed/Europe PMC、出版社/期刊官网及用户有权访问的 CNKI、ScienceDirect、Web of Science 或 Scopus 记录进行交叉核验；
4. 对候选文献去重，区分预印本、会议版和正式发表版；
5. 只有元数据已核验的记录进入参考文献候选表，只有正文证据已读取并能支持具体论断的记录才能标记为 `claim-verified`；
6. 需要登录、机构订阅或验证码时，提示用户通过本人合法权限操作，不绕过访问控制或付费墙。

老师提供的导航页只能作为人工导航入口，不能作为文献真实性证明，也不应作为唯一检索来源。每次实际检索都记录数据库、检索式、检索日期、结果数量、核验来源和访问限制。
## 学术原创性与表达优化

当用户提出“降重”“降低AI率”“改得更像人工”等要求时，加载`references/originality-and-citation-audit.md`，将请求解释为：降低不必要的文字和观点重复、重构论证、提高具体性、保留引用并增强作者自己的研究判断。

执行顺序：

1. 先锁定数据、结果、术语、直接引用和不可改变的事实。
2. 扫描文字重复、结构重复、观点重复、来源依赖和空泛模板表达。
3. 对每段提炼核心论断，绑定真实文献和证据位置。
4. 优先重组段落逻辑和证据顺序，再进行语言润色；不要只替换同义词。
5. 输出修改前后对照、修改理由、引用变化和需要作者确认的地方。
6. 将AI检测结果视为不稳定的辅助信号，不承诺具体分数，不通过错别字、随机标点或事实错误规避检测。

如果用户要求“保证AI率低于某个百分比”或“绕过某个平台检测”，应说明不能保证或专门协助规避检测，但可以按上述学术原创性流程改善文本质量和研究可追溯性。
## 发布会原则（叙事优势导向写作）

当用户提出"帮我把论文写得更有竞争力""按发布会原则改""不要写成工作汇报""重新组织叙事"等要求，或进入写作、修改、压缩、实验组织阶段时，加载`references/press-conference-principle.md`并全程执行。

核心判断：识别本文最值得发表的价值，围绕它建立最有利、最完整、最有说服力的叙事；删除与核心主张无关的内容，收缩证据无法牢固支撑的主张，把不占优的结果解释为目标差异或合理权衡，必要时彻底重构故事。该原则只调整叙事与比较逻辑，不豁免证据核验纪律——优势表述必须真实有据。

## 输出格式

完成任何一个阶段时，按以下结构回答：

1. **本轮完成内容**
2. **已核验事实和文献**
3. **仍待核验或缺少的数据**
4. **生成的正文、表格或文件**
5. **下一步建议**

如果用户要求“一次性生成完整论文”，仍应先给出研究边界、证据状态和明显占位符，再生成初步大稿；不得用虚构内容填满空白。

## 可选外部工具

如果用户已经安装相关GitHub工具，可以将其作为辅助，但不要假定工具一定存在：

- `literature-review-toolkit`：辅助检索、去重、DOI和元数据整理。
- `Auto-Scholar`：辅助关键词扩展和综述初步组织。
- `Universal SLR Assistant`：辅助系统综述筛选和数据提取。
- `Draft Detective`：辅助引用存在性、论断支持性和审稿风险检查。

详细的重复表达、AI风格风险和学术改写规则见`references/originality-and-citation-audit.md`。

无论是否使用这些工具，最终引用都必须回到可追溯来源和作者人工确认。

## 常见错误

- 只根据论文标题或摘要推断全文结果。
- 把Google搜索结果、博客、新闻或AI生成的引用当成正式文献。
- 为了满足参考文献数量要求而添加未读文献。
- 把“相关”“预测”“可能机制”写成“导致”。
- 按时间顺序罗列实验过程写成工作汇报，而不是围绕优势组织论文叙事（见发布会原则）。
- 把系统综述中的二手表述当成原始研究证据。
- 为原始研究补写用户没有提供的样本、统计结果或实验结论。
- 只保留支持自己观点的论文。
- 生成初稿后不再检查正文引用与参考文献表的一致性。
