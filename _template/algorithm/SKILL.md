# 标题

## 何时使用

- 看到某类题不知道方向 / 需要模板 / 判断复杂度是否够

## 条目结构

每个算法条目必须包含四段：

1. **适用条件**：什么题型、什么约束下才成立。
2. **复杂度**：时间 / 空间，以及常数是否要紧。
3. **边界与坑**：空输入、单点、极值、溢出、平台差异。
4. **实现要点**：关键代码或改动位置。

模板见 `references/algorithm-entry.md`。

## 数据范围 → 复杂度

| n | 可用复杂度 |
|---|---|
| ≤ 20 | O(2ⁿ·n) |
| ≤ 100 | O(n³) |
| ≤ 1e5 | O(n log n) |
| ≤ 1e6 | O(n) |
| ≤ 1e9 | O(log n) / O(1) |

## 代码规范

- C++17，可编译；注明依赖与编译命令。
- 不使用未定义行为（有符号溢出、越界、悬垂引用）。
- 模板必须标出"需要改哪里"（多测清空、取模、long long）。

## 测试建议

- 随机小数据 + 暴力对拍，至少 1e3 组。
- 覆盖边界：n=1、全相同、极值、多测。
- 提供 `gen` / `brute` / `check` 三个脚本的骨架。

## 边界

- 他人题解与代码只链接，不复制。
- 平台特有优化必须注明前提（编译器、栈大小、是否允许 `pb_ds`）。
