# 标题

## 何时使用

- 合并前审查 / 上线前检查 / 第三方技能启用前审计

## 检查维度

| 维度 | 看什么 | 典型问题 |
|---|---|---|
| 正确性 | 边界、错误处理、并发 | 空输入崩溃、竞态 |
| 安全性 | 注入、越权、凭据 | 拼接 SQL、明文密钥 |
| 可维护性 | 命名、重复、耦合 | 千行函数、隐式依赖 |
| 性能 | 复杂度、N+1、缓存 | 循环内查询 |
| 可测试性 | 可注入、可观测 | 硬编码全局状态 |

## 严重度分级

- **CRITICAL**：可导致数据损坏、凭据泄露、越权访问；必须阻断合并。
- **MAJOR**：明确缺陷或有现实触发路径；合并前修复。
- **MINOR**：风格、可读性、潜在风险；可排期。

## 输出格式

按 `references/review-report.md` 填写：位置 / 等级 / 问题 / 证据 / 修复 / 验证。

## 脚本安全

- 默认**只读**：不修改用户文件、不执行被审查代码、不上传数据。
- 需要运行命令时，先说明命令与影响，由用户确认。
- 不自动提交、不自动部署。

## 边界

- 误报要标注"需人工确认"，不把推测写成结论。
- 不替代测试：审查通过不等于功能正确。
