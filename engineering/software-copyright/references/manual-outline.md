# 用户手册 / 文档

软著的“文档”可以是用户手册、操作手册、设计说明书或使用说明，任选一种。本 skill 默认生成用户手册，因为最容易用真实界面和真实操作支撑。

## 官方基线

- 文档取连续的前 30 页和后 30 页；不足 60 页全部提交。
- 文档每页不少于 30 行；有图时可少于 30 行。
- 页眉标注软件名称、版本号，与申请表一致；右上角连续页码。
- 文档正文标题写清文档种类，例如“XX 系统用户手册”。

## 推荐结构

```text
封面：软件名称 + 版本号 + 文档种类
目录
1. 软件概述
   1.1 编写目的
   1.2 适用对象
   1.3 主要功能
2. 运行环境
   2.1 硬件环境
   2.2 软件环境
   2.3 浏览器/客户端要求
3. 安装与启动
   3.1 安装步骤
   3.2 启动与登录
   3.3 卸载（如适用）
4. 操作说明
   4.1 功能一：真实截图 + 操作步骤 + 结果
   4.2 功能二：真实截图 + 操作步骤 + 结果
   ...
5. 常见问题
6. 附录（可选）
```

## 写作规则

- 只写真实存在的功能；每个功能至少对应一张真实截图和一段可执行的操作步骤。
- 每个主要功能章节应出现在 `evidence-map.json` 的 `features` 中，并填写对应的代码路径、截图和申请表原句。
- 截图放在 `screenshots/`，路径相对 `evidence-map.json` 所在目录；文件必须真实存在。
- 截图来自实际运行的软件，不用示意图、AI 图、模板图或占位图。
- 截图中的软件名称、版本号、界面文字要与申请表和源码一致。
- 描述“看到什么、点什么、发生什么”，不要写空泛的营销话术。
- 与源码对齐：手册中出现的模块、接口、参数，应能在源码中找到对应实现。
- 不要出现 `TODO`、`待补充`、`待填写`、`lorem ipsum` 等占位内容。
- 不要包含真实密码、密钥、个人信息或内网地址；截图前先脱敏。

## 页数与排版建议

- 常见 15–25 页；不少于 30 行/页（有图页除外），最多 60 页。
- A4 纵向；正文可用宋体/思源宋体 10.5–12pt，标题分级；行距 1.3–1.5。
- 页眉：软件名称 + 版本号；右上角：连续页码。
- 图片清晰，标注图号和图题；关键按钮可加箭头或方框。
- 若实际排版超过 60 页，按官方要求取前 30 页和后 30 页，不要把中间页硬塞进 60 页。

## 截图清单

- 登录/首页
- 每个核心功能的主界面
- 关键操作的结果页
- 权限/设置/日志等能体现完整性的页面
- 异常提示或帮助页（可选）

## 自检

`check --manual` 会检查：

- 是否有有效内容；
- 是否估算超过 60 页；
- 是否包含概述、运行环境、安装启动、操作说明、常见问题等章节；
- 是否有截图；
- 是否含占位内容；
- 名称/版本是否出现在前 40 行。

`--manual` 支持 Markdown/HTML。DOCX/PDF 请先导出为文本，或保留 Markdown 源文件；最终仍要用 Word/PDF 实际排版核对页眉、页码、行数和截图清晰度。
